# 建模与应用集成

## 尺寸与坐标

项目家具字段 `w/d/h`、平面 `cx/cy` 和安装高度使用 mm。当前 Three.js 使用 `M(v) = v / 1000`，平面坐标由 `wx/wz` 转换；先确认当前实现。

2D 图例以家具平面中心为原点，宽沿 x、深沿 y。3D 局部坐标宽沿 X、深沿 Z、高沿 Y；常见模型正面为 +Z，应和 2D 图例前侧一致。当前普通家具组通过 `wx(f.cx), 0, wz(f.cy)` 定位，以 `-f.rot` 绕 Y 旋转，并通过局部 X 负缩放镜像。复用这些变换，避免重复旋转、镜像或加入世界偏移。

外包框应符合标注的 `w/d/h`，明确把手、水口、底盖等是否包含。壁挂件把底部离地高度与自身高度分开；不要用拉长机身模拟抬高。用空值判断保留合法的 0，并为旧数据缺失字段提供明确默认值。

区分两类缩放：布局草模可以整体按比例变形；真实型号的孔距、容量、接口位置及安装要求不能因草模缩放就解释成另一真实产品规格。需要固定参数或派生规则时逐项定义，交付说明缩放的含义。

## 外观与交互

按轮廓、体块、主材质、识别性细节的顺序实现。优先复用已有几何/材质，曲面精度按实际显示需要决定；检查薄面闪烁、负缩放后的面朝向、无效法线和几何数值。保持当前离线资源策略，新增纹理时确认本地加载与成果依赖。

静态产品无需增加虚构交互。门轴、抽屉行程等由资料或明确草模假设决定；持久参数与临时开合状态遵循同类实现。独立预览应使用实际生产构造逻辑，不能用另一个精修模型替代应用中的模型。

## 按需检查的代码入口

| 环节 | 当前位置与注意事项 |
|---|---|
| 家具库 | `src/data/catalog.js`；核对分类、唯一 type、默认尺寸/高度、颜色与价格含义 |
| 文案 | `src/data/i18n.js` 及相关 UI；沿用当前多语言机制 |

| 新建/复制 | `src/ui/furniture-actions.js`；新字段默认值、实例编号与复制规则 |
| 属性编辑 | `src/ui/property-panel.js`；范围校验、锁定、撤销、重绘及自动保存 |
| 规则/替换 | `src/core/design-core.js`，`src/ui/catalog-ui.js`；替换后保留兼容字段、清除不适用字段 |
| 序列化/校验 | `src/core/project-core.js`、`src/core/work-state.js` 与相关 io；当前方案、命名方案、恢复/分享路径按需检查 |

新增持久字段要检查导入范围及类型、缺失默认值、保存与重新加载、复制/替换、撤销/重做。字段影响几何时纳入缓存失效条件。不要因一个模型任务重构整体三维加载或引入新构建流程；项目加载约定见 `docs/ARCHITECTURE.md`。

## 安装与空间检查

安装预留作为独立约束，不加入机身尺寸。左右随产品旋转/镜像变换；空间距离的测量范围应符合实际侧面，不能只用中心射线代表整面净距。

说明算法包含墙体、窗、其他家具、高度错位中的哪些对象。对缺失墙体、未建模吊顶、未知层高或接口信息，返回待核对，而非默认满足。采用当前方案的有效结构，避免拿旧方案或未经应用的草稿核对。

厂家要求、现场实测和程序提示分别标明。项目现有算法的局限可记录在交付说明中；不要为了统一流程自动增加用户未要求的施工级检查。
