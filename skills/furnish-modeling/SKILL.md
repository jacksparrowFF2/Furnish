# Furnish 模型制作

完成用户要求的模型精度与应用集成，并使尺寸、外观、安装信息和验证结果可以追溯。面向 Furnish 应用模型；用户若只要求独立预览或模型方案，按该范围交付，不自动扩展为全部应用功能。

## 输入与资料

先阅读 [输入模板](references/input-template.md)，从已有对话、图片和项目资料填写已知信息，不要求用户重复提交完整表单。关键尺寸、型号对应关系或安装方向存在冲突时，只询问影响当前工作的缺项；其余独立工作继续。参考图不能证明隐藏尺寸、材料性能或安装要求。

每项关键数值标记依据：用户确认、尺寸图标注、项目既有资料、外观估算或未知。未给出的型号、价格和尺寸不得伪造。可按用户授权采用占位尺寸，但须标明假设；缺少决定安装核对结论的数据时，不宣称满足要求。

## 执行流程

1. 确认目标 Furnish 仓库，遵守其中的 AGENTS.md，并查看当前未提交修改。默认可在 `C:/Users/SPH/Documents/GitHub/Furnish` 寻找；路径不存在或用户指定其他仓库时使用实际目标。下文项目路径均相对该仓库，不相对 skill 目录。
2. 阅读 [建模与集成规则](references/modeling-rules.md)，检查当前实现位置与同类模型；文件位置是导航线索，实际代码优先。涉及柜体时再读项目 `docs/CABINET-DESIGN.md`。制作类似壁挂设备或需要具体示例时读 [扁桶热水器示例](references/waterheater-flat.md)。
3. 简要说明采用的尺寸、正面与安装基准、外观精度、交互范围及未确认事项。资料足够时直接实施，不额外要求批准例行方案。
4. 复用已有材质、几何与状态机制，按需要同步家具库、2D、3D、属性及存储。先保证整体尺寸、主要轮廓和安装朝向，再做可识别细节。
5. 按 [产出验收](references/acceptance.md) 检查适用项；记录通过、失败、未执行与不适用的原因。新字段、空间算法与交互需覆盖真实行为；单纯颜色或低影响外观微调不必堆积测试。
6. 交付可查看的模型结果、资料依据与简化说明、必要的预览及实际验证结果。文档与截图路径按项目现有约定放置，最终回复使用可点击的实际绝对路径。

## 必须保持的约定

- 输入、项目数据与界面尺寸使用 mm；Three.js 几何按当前转换机制使用 m，不重复换算。
- 机身外包尺寸、安装离地基准与安装/操作预留分开表达，说明外包尺寸包含哪些附件。
- 左右以面对产品正面为基准，旋转和镜像后随产品方向变化；不能以屏幕左右代替产品左右。
- 对真实安装要求保留其来源与适用型号。模型为布局/外观近似时明确标注，不把视觉近似或有限空间检查描述成施工验证。
- 应用数据修改进入现有撤销与自动保存流程；新字段遵守导入校验、旧数据默认值、复制与替换规则。保留原有型号及用户未要求改变的既有行为。
- 不把热水器的默认高度、预留间距、价格占位或容差推广为其他产品的通用规则。
