# 产出与验收

## 交付内容

应用集成任务通常交付：可从库中使用的模型、匹配的 2D/3D 表现、用户要求的参数/交互、必要的保存兼容、简要模型文档和预览证据。独立预览任务只交付对应范围。

文档可采用项目已有的 `docs/<model>.md` 约定，记录：型号与用途；关键数值及来源；外包与离地基准；简化/省略项；参数和交互；安装要求与算法边界；价格未知等待补项；验证结果及截图位置。原图不在当前资料中时只能声称依据既有记录。

## 按变化选择验证

| 检查 | 适用时的通过条件 |
|---|---|
| 身份与默认值 | 新条目可找到，默认规格正确；没有意外覆盖原有型号 |
| 几何 | 实际生产模型外包尺寸/底部位置符合基准；改变尺寸及旋转/镜像后结果正确；几何与法线数值有限 |
| 外观 | 在应用或生产模型预览中检查正面和斜视；材质、特征与资料相符，无穿插/闪烁等明显问题 |
| 属性与交互 | 参数即时影响模型；非法输入被拒绝；0 值和锁定正确；门轴/行程符合定义 |
| 状态 | 涉及的新配置在撤销/重做、刷新、导出再导入中保留；复制/替换按语义处理；旧数据可加载 |
| 安装规则 | 边界等于阈值、低于阈值、旋转/镜像、未知结构等有正确结果；提示明确包含范围和限制 |
| 回归 | 代码改动后运行 `node scripts/check.cjs`，与模型相关的行为检查通过 |
| 加载兼容 | 改动资源/加载方式时检查原有启动方式和离线约定；不能以服务模式成功证明 file:// 成功 |

数值容差依据几何实现与数据精度选择，不把测试浮点误差当作厂家安装偏差。新规则测试覆盖有意义的边界和实际行为，避免只匹配源码文字。纯文档、截图或轻微颜色改动不需要完整应用回归。

截图用于视觉验收，不能替代尺寸/持久化检查；Node 测试通过也不能替代实际视觉检查。未具备浏览器验收条件时仍完成可执行检查并明确尚未验证的部分，不虚报全部通过。

## 交付结果格式

```text
模型与完成范围：
尺寸、朝向与安装基准：
资料依据及假设：
实现/预览/说明文件：
验证：通过 / 失败 / 未执行 / 不适用，逐项注明证据或原因
简化项与待补资料：
```

面向用户的最终回复压缩为完成内容、查看入口、实际验证结果和影响使用的待补项；无须复述全部核对过程。
