## 几何和交互

- 正面朝局部+Z。照片实际衣物轮廓生成闭合厚片；独立挂钩作为布局参照。背面／侧边采用衣物中部素色采样，没有背面照片，不复制正面拉链伪装背面。
- `w`为含袖最大宽，`d`为模拟厚度，`h`为含帽／挂钩总高；底部离地复用`mountHeight`，新建0。挂衣时将底部升至挂衣杆高度减去总高，检查挂钩和杆的实际关系；本轮不实现自动挂接或宿主字段。
- 尺寸调整、复制、替换、撤销重做、保存恢复和刚体旋转复用普通家具流程。厚度调整只改变深度，图像宽高不变；全高调整会缩放整件，包括参考挂钩，属于布局示意。
- 产品核心声明`footprintMin`，宽至少100、厚至少10mm；属性与库校验共用，跨类型替换按目标能力执行，不复制UI类型白名单。原其它产品最小值保持。
- 数字实体沿真实生产顶点生成；厚度、离地、旋转／镜像进入既有缓存和确认上下文。二维显示平面厚度矩形与正面线。斜视可见封边厚度。
- 每款只有衣片和挂钩两个稳定部件。照片厚片的凹轮廓在显示／GLB中保留；既有凸包实体测距／碰撞会保守填充袖下凹口和弯钩空隙，不据此推定可容纳其它物体。没有柔体受挤、衣架真实结构或服装展开体积模拟。

## 生产与离线

`scripts/lib/garment-photo-specs.json`记录作者参考资料；产品默认值与能力仍由`product-rules.js`管理。Blender作者脚本从保留的原图取UV，轮廓优先读取BG0在线抠图的alpha（阈值0.8，2.5像素折线简化），不重绘衣物照片；独立发布器重新导入GLB，检查部件身份、封闭性、退化面、尺寸、UV和受限纹理。运行时复用`storage-supply-model`／`static-asset-model`，嵌入本地RGBA与UV，断网`file://`无需图片请求。

新衣物沿既有storageSupplyRevision=2选项目v57，`pose3D`仍选v58；没有新增实例字段或保存通道。历史类型和项目版本不提升。

可复现命令：

```powershell
node scripts/build-garment-photos.cjs output/garment-new-build garment-short-down,garment-long-down,garment-autumn-jacket v-new
node tests/test-garment-photos.cjs
node scripts/verify/verify-model-pipeline.cjs garment-short-down,garment-long-down,garment-autumn-jacket gpu
```

构建目录及源版本目录必须为新目录，已有版本拒绝覆盖。正式源按发布资产`sourceSha256`查找，不按目录版本大小猜测。[视觉及验证记录](validation/garment-photo-20261108/README.md)分别记录源外观与生产传递。
