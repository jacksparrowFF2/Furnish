# 上下柜独立布局（第三阶段）

2026-11-07。普通可组合柜可进入「上下柜独立布局 → 设置上下柜不同深度与分格」。整组外宽／总高／底部离地共用，上下柜后沿对齐，深度、横向隔间、分箱、层板、门抽各自编辑。两柜各有实际顶底板，左右见光板为整组连续板件；深度不同不拉伸板厚或复制同一分格。

## 数据与单位

可选 `cabinet.tiers={height,lowerDepth,upperDepth,upper}`：height是下柜完成顶面距柜底mm；上下总深均含自己的门板和背板。整体d取两柜最大值。原cabinet本身是下柜配置，upper只保存上柜配置，避免持久化重复的下柜树。上柜零踢脚，无自身离地；子柜安装偏移在tierParts边界派生，整组mountHeight只叠加一次。柜宽扣整组左右见光板后，作为两柜各自外宽。

规则范围由product-rules.cabinetTiers声明：两柜各至少200mm高、各深150–1200mm；仍受各子柜实际板件、净高和门抽约束。范围是软件能力，不是厂家结构／承重要求。上下同深也沿同一结构；不保存“同深兼容”开关。

含tiers的当前／命名方案、库与工作区最低v67，缓存读取包含v67。与并行收纳盒任务协调，客户端缓存版本基础可为v68，收纳盒阵列仍单独最低v68。旧客户端拒绝新格式，不能忽略upper后只显示下柜。新字段的复制、模板替换清理、恢复与撤销仍沿完整cabinet和原mutate／保存链路。

## 核心与生产

- tierParts提供上下子柜、宽深高和局部XYZ偏移；两柜继续调用生产cabinet-model及第二阶段boxTopology／assemblyLayout，不新增第二套柜箱构造。
- 生产模型在稳定tier作用域中构造；门抽选择携带tier键，场景开合路由到对应子柜，不用下柜列号解释上柜。
- 数值实体仍从同一buildRaw记录实际板件，反映上柜前方退台、双板交界和连续见光板。开启空间按子柜自己的深度和门扇派生，平面旋转／镜像及整组离地各应用一次。
- 二维将两柜按同一后沿及局部位移叠加；depthSections返回各tier区段与实际高度，整组不虚构单一净深。
- 完整tiers配置参与既有实体／3D缓存与空间确认；纯价格及上下柜内doorColor不使空间确认失效。采购规格清除两柜当前门抽姿态。

## 编辑与转换

整组编辑负责总宽高、下柜顶高、两柜深度、底部离地和左右整高见光板。内部按钮复用原柜体设计器；子柜的外宽／深／高／离地和外置见光板由整组控制，避免子柜保存时静默改变整组包络。上柜不另设踢脚，顶封板在上柜编辑；配色可沿各隔间外观控件调整。子柜保存先回整组草稿，整组最后保存只产生一次应用历史；取消整组不写回。

现有同深stackedBoxes可显式转换：各原柜箱分界须齐平，保留下柜层板及原上下门组状态，生成实际独立子柜。原布置和命名方案不自动改写。未分柜首次进入默认按65%总高分配下柜（同时为两柜各保留至少200mm）、按下柜有效净高缩放原内部结构，上柜以相同横向结构和空层板初始化；这些是设计初值，可继续编辑。转换会改变构造，不承诺新几何与旧单柜相同。

新建分柜使用独立布局入口；旧最高层板开关只在已存在该结构时显示，避免新方案继续建立同分格限制。另删除读取旧玄关数据时按editable标记自动补层板的隐式兼容构造，改为读取明确保存的层板；未重新编辑的正式数据不写回。未涉及的旧输入恢复／专用柜体分支不宣称全部删除。

## 范围与边界

本阶段用于普通储物、衣柜、书柜等通用配方；排除固定成品、专用挂衣杆模板、玄关、分层餐边、浴室、厨房和设备嵌合配方的通用转换。这些现有柜型保持自己的构造，不凭通用木箱覆盖设备净空。只有两层、不嵌套；不自动合并上下不同分格，若要整体改型可沿原模板替换。界面暂不在整组层面调整侧收口，转换前已有收口按上下深度分段保留。

这仍是布局与结构设计模型，不新增五金承重、固定节点、板材加工或厂家安装结论。验证见[第三阶段记录](validation/cabinet-upgrade-stage3-20261107/README.md)。
