# 对开门与开启方向

## 逐扇最大开启角度（2026-10-30）

选中建筑平开门，在属性中设置每扇「最大开启角度」，范围 **1–180°**，缺失仍为原有 **90°**。对开门的两项可不同：门扇1位于原始铰链端，门扇2位于另一端；点击任一扇仍联动开关，但各自停在自己的上限。当前开合姿态仍为临时显示，不另存当前角度。单扇门也使用同一规则。

`floorplan-core` 集中定义范围和校验；可选 `hingeAngles` 数组写入 `architecture.draft.openings[]` 或 `work.open.d[index]`，单扇长度1、对开长度2。旧数据不补写。二维门板／弧线、三维生产门轴与漫游实际门板，以及全案检查最大开启扇形共用几何解析。90°与180°端点直接使用原向量，避免浮点残差；超过90°仍沿原开启方向旋转。改门型保留第一项，增加的门扇默认90°；重置恢复原户型角度。

沿原 `mutate()`、撤销重做、自动保存及命名方案／项目恢复通道；内置户型复制、洞口重排和原始结构快照保留角度。含字段的项目／工作区采用v38，恢复缓存隔离为v38并继续读取旧缓存。建筑门仍不进入家具产品规则。下文固定90°及20段的描述为早期实现；现在扫掠按每4.5°一段，180°为40段。

`tests/test-room-door-angles.cjs` 覆盖无效输入、旧门默认和重置、不同门扇角度、横竖墙／反向铰链／内外开、真实生产Three.js门板端点与二维末端一致、超过90°的障碍检测、户型复制／编辑／洞口重排、v38当前及命名方案重复往返。验收记录见 [本次验证](validation/room-door-angles-20261030/README.md)。

空间检查仍为平面扇形近似，没有新增门厚扫掠、竖向避让或五金安装校验。模型可设置180°不代表现场墙体、把手和五金允许180°。

2026-10-18 新增建筑洞口的对开门。选中平面上的门，在属性中将「门的类型」改为「对开门」，再选择「向内开」或「向外开」。户型描图的「添加门」也可直接选择对开门，保存户型后可在主画布调整开向。

## 几何与交互

- 沿用原洞口宽度与位置，两扇等宽，各占洞口宽度一半，铰链分别位于两端；不提供子母门比例。单扇与对开切换不会改变洞口尺寸。
- 高度沿用已有门的 2100 mm 示意值，厚度沿用 40 mm；低墙剖切仍按当前显示高度裁切。这些是原有布局模型值，不是厂家的产品或安装参数。没有新增报价或虚构型号。
- 向内以原户型开启侧为参照，向外取相反侧；入户门继续使用固定的入户方向。自定义户型的新门先设置「向内侧」，内部房门两侧均为房间时，需按自己的房间约定核对。切换开向会将两个门轴移到墙的另一面，使闭合门板留在墙厚内。
- 二维分别绘制两扇半宽门板和 90° 弧线；三维两扇在各自外侧门轴旋转，点击任一门扇或把手时联动。三维当前开合仍是临时显示状态，保存的是门型和开启方向。
- 漫游按每扇实际宽度检查门板，不再固定取 900 mm。门窗表将对开门记为两扇。重置会恢复原洞口的门型、铰链与开向；原户型自身为对开门时，重置仍为对开门。

## 数据与兼容

`architecture.draft.openings[].doorType` 和 `work.open.d[index].doorType` 为可选枚举 `single/double`。前者只允许用于 `kind:door`；后者与原有 `h/c/o` 同存，由项目导入校验。缺失仍读取原单扇，不补写旧持久数据。新增门显式保存门型；向内／向外复用原有向量，不增加另一套方向持久字段。

建筑门不属于家具产品，字段校验和生成留在 `floorplan-core.js`；不加入家具 `product-rules` 能力或家具替换白名单。`layout-geometry.js` 共用 `doorLeaves()`、`doorSwingPolygons()` 与 `doorOverride()`，二维、三维、全案检查和高亮读取相同几何。后者也统一旧版只反转开启向量而未移门轴的恢复行为。

工作覆盖通过原 `mutate()`、历史、自动保存、命名方案和项目打包链路保存。复制内置户型时 `fromPlan()` 保留门型，洞口调整的 `remapOpenings()` 保留门型覆盖。没有新增资源、加载机制、独立保存通道或项目外层版本；原项目版本兼容策略沿用。

建筑缓存已有完整 `state.open`；空间确认已有有效 `plan.doors`，两者覆盖新门型和开向。撤销、重置及方案切换会先恢复原门型，避免运行时副本残留对开设置。

## 仅有矩形门洞的兼容（2026-10-18）

只有 rect 的图纸洞口不具备门轴／开启基准。`doorOverride()` 保留此类记录和部分向量；即使叠加完整 h/c/o 保存覆盖，原始基准缺失时也不执行跨墙面门轴换算，不推定未知开启侧。向量数组在派生结果中复制，源记录不受影响。`test-drawing.cjs` 验证无向量、部分向量、完整覆盖、运行时 _base、当前／命名项目往返以及重复恢复保持洞口尺寸与数据。原单门／对开门完整几何的换向语义保持。

本次从头 `node scripts/check.cjs` 通过 **207/207** 套回归、12 个内置户型、16 个重建预览及资源／共享声明／生产语法检查。门体与包管柜 HTTP／离线 file:// 浏览器复验通过。[完整回归记录](validation/door-restore-20261018/regression.json)，[浏览器结果](validation/door-restore-20261018/browser-results.json)。未执行实机触屏和施工安装验收，原算法边界保持。
