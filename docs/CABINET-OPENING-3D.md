## 通用上下翻与独立门角度（2026-10-14）

储物门和展示门均支持侧开、对开、上翻、下翻及无门。有效最大角度优先读取单区／模块设置，再继承整柜；当前观察角度不缩小空间核对范围。上下翻复用生产门板位置与水平门轴，分别按负／正角绕 X 轴扫掠，延用不超过 2° 的剖面间隔。玄关和分层柜每段门板保留自身高度与深度；壁挂安装高度同时平移 `ranges` 与 `sweep.profile`，避免只移区间漏移剖面。无门不生成门开启区。

浴室柜未编辑的历史静态组件不虚构开合；保存箱体设计后从产品规则读取离地高度，房间组件、门板扫掠与管道运动板件保持同一基准。服务核心 `local(f,pipe,{cabinetOnly:true})` 将管道转为箱体局部高度，完整浴室柜组件切孔仍使用原房间局部高度。管道检查继续复用生产记录与实际切孔的板件，X/Y 门轴均由运动模型派生，不用未切孔扫掠代替。

空间确认上下文增加 `cabinet-door-directions-v1` 规则标记，嵌套门型与最大角度进入既有确认和缓存输入。旧确认记录保留但需按新规则复核；配色与采购编辑不清除空间确认。新增测试核对生产网格、旋转镜像、安装高度、接触边界、未知高度和实际恢复；本轮验收与模型边界见 [改进记录](IMPROVEMENTS.md)。五金连杆、自身干涉和多门同时运动仍不模拟。

## 规则与表现

| 对象 | 检查范围 |
|---|---|
| 竖轴柜门 | 既有最大角度扇区 × 实际门板高度区间；玄关上下门的开放置物区不纳入门板高度 |
| 分层餐边柜 | 下柜门、上柜门与冰箱位顶部门分别使用自身高度和前沿深度；上下柜同深时也保留两个独立高度区间 |
| 抽屉与上盖抽屉 | 完全拉出行程仍为对应柜深的 70%，使用实际抽屉组／整体上盖抽屉的高度 |
| 玻璃上翻门 | 沿顶部横轴，从关闭姿态扫到配置的最大角度；使用门高、板厚和玻璃框厚，超过 90° 的部分进入铰轴上方 |
| 抽屉操作空间 | 拉出后的净距仍由既有通道阈值控制；竖向范围单独按地面至 2000 mm 的站立操作布局假设，不随抽屉高度上移 |

高度没有正重叠时不报告物理冲突，面接触不算穿入。平面仍沿用既有 5 mm 接触容差。未知家具高度显示“待核对”，不认定满足，也不表述为已确认实体冲突；单项、多选和柜体编辑器以提示样式显示。

柜体编辑器的明确冲突保留警示色，避免弹窗通用段落颜色将其覆盖成普通说明文字；未知高度仍使用待核对提示样式。

上翻门不能只用整体三维外包框判断。其局部深度/高度截面按不超过 2° 的角度间隔形成扫掠剖面，沿玻璃门宽度挤出。检查时先裁剪障碍在门宽内的投影，再裁剪剖面与障碍深度/高度区间，剖面外包框中的空角不会被当作门板。

## 顶部和墙体障碍

- 柜体开启检查纳入已有高度包络的壁挂空调、电视、镜子、吊灯等，不能沿用地面占地检查的壁挂豁免名单。
- 全高墙使用当前项目完整高度；矮墙沿用生产模型的 1000 mm 上限。观察用剖切高度不改变物理检查。
- 天花板/吊顶按各房间有效净高检查整个扫掠投影，跨越较低相邻房间时也检查该部分，而不是只查询柜体中心所在房间。无房间列表的几何测试使用项目默认净高。
- DXF 梁已支持梁底／梁顶录入，完整高度参与三维开启检查；旧梁无高度时保留待核对。数据与验收见 [房梁高度](BEAM-HEIGHTS.md)。现有结构核对记录仍保留。
- 柔性窗帘、植物和地毯不作为此项刚性开启障碍；其他家具使用既有产品垂直包络和旋转外包占地。

## 模块接口

`FurnishCabinet.openingZones(f,{passage})` 仍保留 `kind`、`column`、`poly`，新增派生 `ranges`（毫米高度区间）、`section` 及玻璃门 `sweep`。这些字段仅在检查时生成，不写入家具配置。

`FurnishCabinet.openingIntersects(zone,polygon,vertical,intersects)` 为共同的空间判定入口，`project-core.js` 调用它检查墙、家具、天花板和未知梁。属性面板、编辑器、全案及成果核对继续消费同一项目规则。

空间确认升为 **v3**，上下文加入项目/房间净高、房间分块及梁投影。旧数组和 v2 确认记录保留，但不自动视为已完成本轮三维核对；需重新确认。价格、采购状态和颜色仍不进入空间确认上下文。

## 适用边界

检查用于布局核对，其他家具按静态外包范围表示；不逐板分析其他柜体的开放空腔，也不模拟两扇柜门同时开启、软装变形、五金安装或柜体自身铰链/板件干涉。上翻姿态沿用既有可配置的展示角度，并不代表真实产品五金能达到该角度。极小间隙需按真实产品和现场核对。

2000 mm 站立操作高度是本轮明确记录的布局假设，不是人体尺寸标准或强制规范。梁高和其他未知尺寸需补资料。小屏验收为 Chrome 视口模拟，未进行真实手机触屏验收。

## 整体障碍提示与独立门扇（2026-10-25）

空间检查继续使用高度裁剪后的实际板件与完整扫掠，所有板件仍参与碰撞。只在命中结果中按家具 ID 汇总已知／未知高度的名称，避免床、椅、喂食器的多个板件使同一名称重复数百次；两个同名但不同 ID 的家具仍分别显示。最终去重对 cabinet 开启类记录包含扫掠定位点，同一隔间、同一文案的两个门扇不会被误合并。

保存的核对记录不删除；受影响条目的说明／定位改变后可能需要重新核对，其他空间规则和价格配色行为不变。`tests/test-cabinet-obstacle-messages.cjs` 验证多板件、同名不同家具、旋转镜像、高度分离及两扇相同文案的独立定位。当前方案保留原有提示并恢复一条此前合并的门扇记录。见 [全量记录](validation/full-regression-main-20261025/README.md)。
