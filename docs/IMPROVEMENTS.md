# Furnish 主线改进与验收

主流程：自己的户型 → 房间用途 → 家具与材料 → 两套方案比较 → 导出成果 → 在另一个浏览器继续编辑。

## 2026-10-09：项目目录整理

- 根目录保留页面、启动入口、清单与仓库说明。业务代码按 `src/core/`、`src/io/`、`src/ui/`、`src/data/` 归类；主应用与主样式分别位于 `src/app.js` 和 `styles/app.css`。
- 测试归入 `tests/`，开发脚本归入 `scripts/`；示例、模板、图标、文档与说明截图分别归入 `examples/`、`templates/`、`assets/icons/`、`docs/`。
- 内置户型由浏览器与 Node 共用 `src/data/plans.js`；几何校验和项目门窗回归直接读取数据，不再从 HTML 截取执行。
- 检查脚本递归扫描源码与测试，并验证页面的本地资源引用；单个测试通过公共路径辅助方法读取样例，不依赖调用目录。
- PDF.js 动态导入按编辑器新位置更新；worker、字符映射与字体等资源仍按页面地址解析。三维模块及内嵌 Three.js 暂时保留在 HTML，继续使用原有离线加载方式。
- 验收：`node scripts/check.cjs` 的 28 个回归脚本、12 套户型校验、递归语法检查与入口路径检查全部通过；从项目外目录单独执行 DXF 模板测试也通过。独立 Chrome 会话验证 2D、3D 画布及示例 PDF 底图渲染，控制台无错误。
- 浏览器工具禁止导航到 `file://`，本轮未实测双击打开。后续拆分三维代码前应先补做真实本地文件验收；风格测试目前仍从 `src/app.js` 截取函数，后续可结合风格模块拆分进一步解除文本定位依赖。

## P0：自定义户型与内置户型一致性

- 房间用途使用独立 `use` 字段，包含未分类、客厅、餐厅、卧室、书房、厨房、卫生间、阳台、玄关／走廊、储物、其他和飘窗台。
- 旧项目通过名称／内置房间编号迁移，用户明确设置后不再依赖名称猜测；飘窗用途固定。
- 房间用途在房间编辑、批量设置、风格匹配、户型库卧室／卫生间计数、拆墙后的空间匹配、命名方案、项目备份中保持一致。
- 厨房、卫生间、阳台、飘窗台和明确设置的其他用途不被风格方案覆盖。未分类自定义房间采用公共空间地面；用户可随时分类。
- `test-design-workflow.cjs` 和 `test-style-presets.cjs` 覆盖迁移、显式用途优先、旋转位置、方案保存与导出往返；原门窗、结构和预算回归继续运行。

## P1：精准布置与方案交付

- 家具属性增加四方向距墙尺寸输入，以旋转后外包边缘为基准，输入 0 贴墙，沿原有方向移动；没有对应墙面时禁用输入。
- 聚焦距墙输入时，画布高亮实际对应的墙面并显示距离；更新位置或失焦后清除参考线，成果导出不包含编辑参考线。
- 锁定、无效尺寸、最终位置穿墙或超出房间会拒绝并在面板解释，修改可撤销／重做。
- 复用现有多选对齐、等距分布、拖动贴墙与家具参考线。
- 项目工作台默认提供五步流程入口，衔接原始户型、房间用途、布置／空间检查、命名方案比较／预算、成果／备份。
- 成果 HTML 包含完整平面、可选当前三维图、材料、家具、工程明细、完整预算和可编辑项目；自包含，可离线打开、打印为 PDF、下载项目。
- 复用已有同户型 A/B 比较、备注、同步缩放／平移与预算差值；不新增重复的方案存储体系。

## P2：观察体验与稳定性

- 3D 定位选中房间、家具、门窗，飘窗按整组定位。
- 退出 3D 前保留视角截图；编辑方案或切换户型后旧截图失效。成果导出只使用匹配当前方案的效果图。
- 新业务逻辑放在 `design-core.js`，交互／交付放在 `design-ui.js`，避免继续集中到主 HTML。
- `node scripts/check.cjs` 统一验证生产脚本（含三维模块）语法、全部自动测试和内置户型几何。无需安装测试依赖。

## 浏览器验收

使用独立浏览器会话，不覆盖用户实际项目。验收自定义混合墙厚／飘窗户型：批量用途 → 风格 → 距墙 130 mm → 撤销／重做 → 保存 A → 修改 → 保存 B → 比较 → 刷新 → 成果导出 → 另一浏览器加载项目。

检查内置户型的用途和风格、桌面及窄屏面板、3D 定位／截图、成果内嵌项目的完整性和继续编辑能力。

2026-10-08 已通过上述浏览器流程：自定义房间用途、距墙 130／330 mm、撤销／重做、独立 A/B 比较、刷新、HTML 下载与内嵌项目完整性、第二浏览器从户型库加载并继续编辑、三维整组定位／效果图导出／旧截图失效、内置户型风格兼容、390 × 844 窄屏房间设置。

后续可以在这条流程稳定后，再扩大真实户型样本、优化材质和灯光、增强家具品牌模型以及更复杂的 CAD 兼容性。

## 第三轮：检查、预算与交付一致性（2026-10-08）

- `effectivePlan` 为每份方案独立生成有效几何：恢复原始门窗、套用该版本的开启方向和窗高，剔除已拆墙体。方案比较、预算、距墙操作、空间检查和报告共享此入口，避免当前画布污染保存版本，自定义旧窗高覆盖也纳入预算。
- 修复切换户型时把调整后的铰链／开启方向覆盖成重置基准的问题。推拉门洞口涂刷扣除与三维模型采用相同预设高度。
- 空间检查补充家具重叠和边缘越界；重叠定位同时高亮两件家具。核对状态指纹统一包含房间、墙体、门方向及家具几何／使用空间，相关改变后失效；报告采用同一核对状态。
- 成果报告增加门窗宽、高、窗台高和飘窗进深清单，三面飘窗作为一组。门高标明为模型预设估算。记录待核对、已核对并忽略的事项和未分类用途；报告仍可正常导出并附带可编辑项目。
- `test-design-consistency.cjs` 验证独立版本、门窗工程量、拆墙后检查、重叠／越界、核对状态失效和飘窗整组清单。14 组自动测试、12 套内置户型及生产脚本语法通过。
- 独立浏览器验证当前／保存预算隔离及一致性、切换后门方向重置、检查与报告共享核对状态、真实 HTML 下载。自定义混合墙厚／飘窗样本验证窗高预算更新、三面飘窗合并、未分类用途、内嵌项目校验及窄屏空间面板；无页面运行错误。

## 第四轮：操作恢复与存储可靠性（2026-10-08）

- 定期快照改为编辑前状态；清空／重置／加载命名方案、项目或分享前额外保留。更新／删除命名方案也保留该版本的旧内容。文件菜单提供恢复记录，可手动保留、查看时间／原因／数量、预览平面家具、确认恢复、导出记录为可编辑项目；恢复前再保留当前工作，支持撤销／重做并保护已确认原始结构。
- 每户型最多 8 条，总计 64 条；记录超出约 32 MB 时淘汰较旧项，至少保留最新一条。恢复记录新增 IndexedDB 通道；缓存不足时仍能从较大存储恢复。记录按户型删除时两种存储同步。
- 保存状态区分缓存失败后的“正在保存”、成功及两种存储同时失败后的“未保存”。清除本机数据使用应用内确认，并在写入队列完成后清除 IndexedDB 与缓存，防止旧项目复活。
- 项目加载先校验全部版本和合并数量，失败不改变当前工作；同名不同内容自动改名、相同版本去重；自定义原始基线冲突使用统一副本转换，包含原始结构历史编号。
- 15 组自动测试、12 套内置户型和生产语法通过。独立浏览器验证清空取消、刷新后恢复 46 件家具、预览取消／导出／恢复、撤销重做、缓存配额失败时项目与记录从 IndexedDB 恢复、双存储失败提示、窄屏面板、完全清除后数据不复活。导出的恢复点校验通过；同名合并、重复导入、超限拒绝和更新前恢复点验收通过。

- 16 组自动测试、12 套内置户型与生产脚本语法通过；独立浏览器验证分组、状态备注、预算一致性、不同规格报价、撤销／重做、筛选、空价格拒绝、资料编辑、刷新、真实 CSV／报告下载与窄屏。另一浏览器实际从户型库上传项目，采购资料恢复、继续编辑和小数报价／报告导出通过；无页面运行错误。

### 金额精度调整

按用户要求，界面、方案比较、交付报告及报价／采购 CSV 的金额统一四舍五入到整数元；内部原始价格和预算计算保留精度。例如录入 399.5 元，显示／导出为 400 元。全部自动检查通过。
