# 柜体共享组件（2026-11-07）

普通柜、置物台柜、分层餐边柜共用生产组件。厨房模块、保留结构吊柜、洗衣附属柜仍由各自核心派生普通柜配置后调用同一构造器。配置配方负责结构限制，组件负责同类部件的一致构造；不增加一套持久化组件树。

## 职责

| 层 | 共享内容 | 配方保留的约束 |
| --- | --- | --- |
| `cabinet-core.carcassFrame` | mm 柜箱外宽、箱体高、总深、板厚、踢脚、门后箱深及上下分柜界面 | 独立箱／共享隔板、模块与内部隔间尺寸链仍沿 `boxParts`／`layout` |
| `cabinet-model.createComponents` 的 `board`／`rearPanel` | 生产板件、分柜切板、背板实体与身份；固定成品倒角沿原范围 | 置物台侧镂空、连续台面、共享侧板、餐边柜深浅分段及设备位由配方选板 |
| `shelfFrame`／`drawerFrame` | 核心净深与抽盒前后基准，只在渲染边界转成 m | 活动层板、台面和不同功能区分别选取已有深度分段 |
| `door`／`mountDoor` | 有限板厚门轴、当前角度、最大行程、面板与尺寸标记、玻璃／半透明预览、部件选择、轴厚补偿 | 各段上下沿、分扇和铰链、餐边展示门边框、挂衣柜分段、门板下延及封板退让 |
| `drawer`／`drawerBox`／`mountDrawer` | 独立抽屉状态、行程、底／侧／后板、随动选择标记 | 浅抽排、抽屉高度、分列和抽面范围；木抽盒尺寸统一由 `drawerBoxParts` 派生，见下文升级第一阶段 |
| `handle` | 条形／圆钮／无把手语义；圆钮统一为原普通柜已有的直径 25mm 球体近似 | 条形把手尺寸及放置沿各柜型既有布局参数，不作为五金厂家规格 |

抽拉顶盖、洞洞板检修盖和碗篮仍保留专用机构。碗篮共用抽屉运动与选择组件，其金属托架不替换成木抽盒。普通柜配方不获得置物台／餐边柜的特殊能力，反之亦然。

## 修复的一致性问题

- 置物台抽盒内部板补上与普通柜、餐边柜一致的 `cabinetDrawerBoard` 角色，选中与数值生产板件读取同源。
- 分层餐边柜的门／抽屉选择 `knob` 时实际生成圆钮，原来仍生成条形。沿原位置随门抽运动；条形、无把手及展示框保持。该配置几何有变化，`hardwareComponentRule=round-knob-v1` 定向更新空间确认上下文；厨房保留结构或附属柜也传播该版本。其它柜型及仅价格／颜色编辑不受此版本影响。圆钮沿既有数值记录器契约作为附件，不新增板件碰撞语义。
- 上下分柜的上半侧／背板复制结构标记时保留自身生成身份，修复原来把下半板身份覆盖上来导致正式导出拒绝重复编号的问题。板件顶点、位置和保存结构不变；只有原来重复的上半板恢复其已有 authored `upper` 身份。

## 兼容与扩展

仍读取原 `cabinet`／`kitchen` 数据，不批量补字段，不改项目版本、安装离地、复制、恢复、命名方案和保存／撤销通道。生产显示、预览和 `CabinetMotion` 数值记录器调用同一组件。原调用点的 author site、列／门扇／抽屉分列 scope 保留，不用创建顺序替代身份。

后续通用门抽与板件修复应进入共享组件，配方只提供尺寸、位置、饰面和部件身份参数。新增配方仍须验证自身结构约束；本次未将固定成品资产改成通用木箱。

验证范围、实际旧方案对照与桌面证据见 [本次验收](validation/cabinet-components-20261107/README.md)。

## 柜体升级第一阶段：统一木抽盒（2026-11-07）

用户明确允许舍弃旧柜体兼容。后续按可验证阶段推进；本阶段取消普通柜与分层柜的历史抽盒宽度差异、以及缺失独立背板厚度时仍强扣一块侧板厚度的分支。不保留旧抽盒几何版本开关；现有数据在加载新构造器时直接使用新结构，文件无需改写。其他尚未涉及的历史恢复分支暂存，不能据此称全部兼容代码已移除。

`product-rules.cabinetDrawerBox` 定义统一布局配方：每侧预留10mm、底板厚12mm、底板底面相对抽屉基准抬高12mm、侧板上方留6mm；侧板和后板厚沿柜板厚。这些是软件布局值，不是滑轨、承重或厂家加工要求。此前普通柜底板宽仅扣20mm，分层柜扣双板厚，侧板内表面又不匹配底板边；本阶段统一为：

- 抽盒外宽 = 分列净宽 − 2×侧预留；底板／后板宽 = 抽盒外宽 − 2×柜板厚。
- 侧板内表面与底板左右边缘相接，侧板底面贴底板顶面；后板左右边缘也对齐底板。
- 底板和侧板后沿贴后板前沿，前沿贴原抽面内表面；后板后沿以真实柜背板内面为基准，无背板即从柜后边界计算。
- `cabinet-core.drawerBoxParts` 输出毫米板件，生产组件只换算米并赋原有身份；不再接收各柜型的 `bodyWidth` 修正量。普通柜、置物台和分层餐边柜沿同一构造。
- 校验调用同一板件派生，拒绝负净宽、非正净深和零侧板高度，编辑沿原草稿／mutate，在保存前失败。

抽面、开合百分比、行程、分列、柜箱及安装标高保持各自现行语义。上盖抽屉和金属碗篮是不同机构，未替换成木抽盒；碗篮的前后基准也读取真实背厚。普通柜和厨房派生／附属柜的空间上下文追加受限 `drawerComponentRule=1`，无抽屉柜不新增该标记。颜色、价格不清空间确认。配置和尺寸继续覆盖现有运行期缓存，换代码后刷新创建新缓存；不新增持久字段／加载脚本。

后续阶段顺序：柜箱／隔间组合关系 → 上下不同深度与分格 → 局部无底／层板退让 → 专用配方与旧恢复代码收敛。每阶段独立验证生产板件、开启空间、保存恢复及界面；本阶段未实现这些后续能力。

验证证据见 [第一阶段记录](validation/cabinet-upgrade-stage1-20261107/README.md)。

## 柜体升级第二阶段：统一柜箱与隔间组合（2026-11-07）

`boxTopology(c)` 是横向组合关系的唯一解释入口：每个隔间都有柜箱编号、箱内序号及柜箱首／末格标记，相邻隔间关系决定单隔板或双侧板。`assemblyLayout(f,c)` 在此基础上一次派生毫米净宽、分配外宽、柜箱外宽及位置。一个共享柜箱是含多隔间的一箱，全独立柜箱是每箱一格，混合结构是连续隔间归入同箱；三个情况共用同一算法。

- N个隔间、B个柜箱的结构占宽 = (N+B)×板厚 + 两侧见光板厚；总外宽同时闭合柜箱宽之和与隔间分配外宽之和。
- `widths/layout/moduleLayout/boxRanges/boxJoints` 只投影统一组合数据；编辑器分组、模块复制／排序映射、门板覆盖范围、顶封板分段、三维构造和二维独立柜轮廓读取同一关系。
- `boxParts()` 对共享柜箱也返回一箱，不再以空数组表示共享模式；派生子柜显式使用shared，不再通过删除模式字段依赖缺省构造。原生产部件site与全局隔间索引保留。
- 自动配门始终在每个独立柜箱内进行，包含全为独立、没有shared字段的情况。修复此前按整组总宽重新分配门与分界的问题：例如450／900／660的独立箱不能因自动配门变成另三段宽。门扇数与隔间数可以变化，物理柜箱边界保持。
- 普通可组合柜的结构树始终显示“柜箱N · 隔间M”，不再仅在持久数组含shared时显示归属；模块操作预演直接显示真实箱数变化。专用玄关／餐边／厨房等保留原配方入口，未据此开放普通结构转换。

本阶段删除旧的按目标数量猜结构占宽的 `structureWidth(c,count)` 分支、自动配门中另一套独立柜宽度扣减式，以及UI中“有shared才分箱”的判断。均分先构造目标隔间，再用统一拓扑计算实际占板；没有保留旧公式开关。旧项目输入／玄关历史结构等尚未涉及的恢复分支仍待后续处理，未宣称全部兼容代码已去除。

不新增项目字段、格式版本、脚本加载或保存通道。既有布局只读时的几何／身份保持，因而不无故升级空间确认；自动配门产生的实际配置变化仍由已有完整cabinet签名使确认和缓存失效。价格和颜色不改变分箱。上下不同深度、上下不同横向分格不在本阶段内。

验证见 [第二阶段记录](validation/cabinet-upgrade-stage2-20261107/README.md)。

## 柜体升级第三阶段：上下柜独立布局（2026-11-07）

可选cabinet.tiers把原根配置作为下柜，独立upper配置作为上柜，tierParts统一两柜的尺寸和局部位置。上下可不同深度、不同隔间数及分箱，仍复用同一生产构造；外侧见光板保留整高，门抽选择增加临时tier键。整组只保存一份下柜配置，不复制一套持久下柜树。当前／命名／库／工作区最低v67，沿原mutate与缓存。

新建分柜入口改为完整上下柜设计，旧最高层板开关只供已有结构取消／转换；移除旧玄关读取时自动插入层板的兼容分支。其他专用柜与旧数据恢复尚未全面清理。参数、操作、限制和实际验证见[上下柜独立布局](CABINET-TIERS.md)。
