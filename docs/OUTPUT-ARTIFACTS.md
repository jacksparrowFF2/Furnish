## 全新克隆后的预览

运行 `node scripts/generate-previews.cjs`，从维护源码重建当前 19 个独立预览页面。命令无需 npm 安装或网络，执行后按照控制台／模型文档中的本地 output 路径打开。单个模型仍可运行对应的 `scripts/preview-*.cjs`；方太两款设备共用 `scripts/create-fotile-previews.cjs`。

玄关柜二会先生成其依赖的洞洞板柜预览，不要求克隆中已经存在兄弟 HTML。餐边柜及扁桶热水器分别由 `scripts/preview-sideboard.cjs`、`scripts/preview-waterheater-flat.cjs` 重建。浏览器验证脚本如需预览页面，先运行生成命令。

2026-10-16 模型入口分批调整后，冰箱、热水器、洗烘与三联动预览全部直接加载生产模块；19 个生成器均能在入口只有离线 import map、没有家具代码时运行。引擎映射仍从入口统一读取；不增加打包或联网依赖。当前 HTTP／断网文件实测范围见 [第二批记录](validation/model-entry-batch2-20261016.json)。

生成命令会更新本机同名预览；不要用它保存人工修改过的唯一版本，维护内容应回到脚本或模板。本次整理没有运行它覆盖本机旧文件，生成验收在独立临时副本中完成。

## 链接和验证

文档中的图片链接指向仓库内的长期证据。预览链接指向生成脚本；文档代码片段中的 output 截图／日志路径表示当时的本地产物，在全新克隆中不会自动出现。清理索引见 [本次迁移清单](validation/output-cleanup-20261016.json)。

`node scripts/check.cjs` 继续运行全部测试；新增干净副本验证会在没有 output 的临时目录中重建预览，检查共享脚本声明、模块语法、离线引擎和本地依赖。现有本机预览仍由 check 按适用范围额外检查。资料链接检查覆盖长期资料、技能文件和生成器入口。

本次完整检查通过 172 套回归；284 个本地文档链接、全部归档路径和 UI 报告图片引用通过检查。另在独立的本地服务夹具中实际打开新生成的餐边柜和热水器预览，确认模型显示且无页面错误；没有操作当前项目。`file://` 实机验收受浏览器工具协议策略限制未执行，离线引擎及路径只做了生成／语法检查，不能将 HTTP 结果视为 file 验收。

取消跟踪不会删除本机文件，也不会移除已提交的 Git 历史。测试截图和日志今后留在 output；需要归档的证据再明确复制到 docs/validation 并补充说明。

其他已经克隆过本项目的电脑在拉取这次取消跟踪的提交时，Git 会移除原先受跟踪且未修改的 output 文件；需要保留那台电脑的旧产物时，拉取前先备份其 output 目录。本次已为当前电脑逐文件校验并保留原件。


## 测试目录自动收尾（2026-11-05）

浏览器调度器、模型整链路和桌面验收共用 `scripts/lib/test-artifacts.cjs`。每批新建独立目录，写入运行身份与排他锁；同批用例共用一份工作副本，不跨批复用旧测试结果。复制优先尝试文件系统克隆，系统不支持时退回普通复制，不用可能连带修改源文件的硬链接。筒灯与五个分水器独立用例复用调度器工作区，各 HTTP／file 模式仍使用独立浏览器上下文。

- **成功**：浏览器与模型批次移除登记的源码、引擎和模型资产副本；保留报告、日志、截图、GLB／BLEND、项目快照及未登记为临时文件的新增成果。预览准备阶段和复制的文档记录内容哈希，只移除未变化的基线文件，新建或改写的成果留在原路径。桌面验收在浏览器、窗口关闭且源方案校验通过后再收尾，并移除本批浏览器 profile。
- **失败／准备失败**：保留整个现场并记录失败信息；13个缓存／项目往返单元测试共用退出钩子，正常成功时删除合成夹具，非零退出和未捕获异常时保留。
- **运行中／中断**：不扫描其它任务、不按目录年龄或名称清理。运行锁阻止另一任务接管同一目录；强制中断会留下锁与现场，绝不自动偷锁。确认记录中的进程已结束、且无子进程使用后，才可人工移除该批 `.furnish-test-lock.json` 再续跑。
- **主动保留**：运行前设置 `FURNISH_KEEP_TEST_WORKSPACES=1`，或在批次根目录创建 `.keep`。成功也保留完整副本，适用于调试、视觉精修和需要复用副本的任务。

```powershell
$env:FURNISH_KEEP_TEST_WORKSPACES = '1'
node scripts/verify-browser.cjs portable-smoke
Remove-Item Env:FURNISH_KEEP_TEST_WORKSPACES
```

清理仅针对本次登记的可重建路径；路径越界、符号链接／junction、身份异常或清理失败均保留剩余内容并提示，不掩盖原测试错误。旧无标记目录和已存在的失败现场不自动迁移或删除，当前桌面程序 `output/desktop`、正式项目和既有精修绑定不在清理范围。新脚本应复用公共模块，不另加按时间全盘删除的逻辑。

模型失败批次仍可沿 `--resume` 复用已通过的型号配置及共用专项结果；输入／程序指纹检查保持。已成功清理的批次只能查看成果，不能继续复用其已删除的源码副本，应新建批次；需要续用时预先保留工作区。必要成果默认不设自动过期，长期资料仍按上文归档。其它尚未接入的独立维护脚本维持原行为，不将本次范围表述为所有 output 都可自动清除。
