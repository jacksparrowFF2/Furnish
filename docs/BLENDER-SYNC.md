## 使用

1. 项目目录运行 `node scripts/serve.cjs --open`，进入三维；室内效果图建议选择全高墙并显示所需顶面。
2. 打开「Blender 渲染 → 持续同步 · 试用」，下载 `furnish-sync.zip`。
3. Blender「编辑 → 偏好设置 → 插件」菜单选择「从磁盘安装」，选择 ZIP 并启用 Furnish Live Sync。在三维视图按 N，打开 Furnish 页签。
4. 从 Furnish 复制本地服务地址及连接密钥，粘贴到插件，点击「连接并持续同步」。首次建议新建空 Blender 文件，避免与普通导入模型叠放。
5. Furnish 点击「立即推送场景」或开启「自动推送布局变化」。两端分别显示推送与接收状态。随后可在 Blender 调材质、布光、设置机位，正常保存 `.blend` 和渲染。

自动推送等待三维布局稳定，拖拽期间不打包。关闭面板仍继续，切回二维暂不推送，回到三维后检查变化。刷新页面关闭自动推送；重开 Blender 文件需重新连接。服务重启更换密钥，请重新复制。Furnish 停止推送与 Blender 停止接收分别控制。

默认「保留 Blender 材质」。关闭后下次接收采用 Furnish 材质／配色；选项本身不触发相同版本重新接收，可停止并重新连接。选中受管理物体可勾选「保留此物体的 Blender 姿态」，例如保留窗帘打开或电视转向；这只保留变换，几何仍由源更新。

旧工程可选「接管同名旧导出对象」：仅适用于同一保存版本、可唯一匹配的旧对象，首次接收先验证匹配再接管。失败会暂停，建议新建同步文件后迁移精修材质。原 1601 样板与当前模型版本有差异，不能保证直接接管。

## 同步契约

- 每次发布生产场景完整 GLB；家具移动、旋转、镜像、尺寸、增删、撤销恢复和可见性进入快照，价格等非三维编辑不触发。不是鼠标每帧或动画直播。
- 家具保存 ID 与生产子节点路径保留为传输标识；已标记部件另附实例范围内的角色链和局部位置排序身份。优先按部件身份匹配，子节点重排、无关部件插入、整件旋转镜像不误接到其他角色。同类部件数量变化时，在保留材质模式下拒绝不可靠继承；删除材质暂存也带数量约束。旧快照、未标记或位置重合不可区分的部件仍按原路径匹配，不能保证任意结构重写后的材质归属。建筑无角色时继续使用图层及序号，实例网格在同步边界展开。
- 保留原 Blender 对象并替换网格／源变换；部件类型和材质槽数量兼容才保留精修材质。源删除只删除受管理对象，材质暂存并设 fake user，Furnish 撤销后恢复；隐藏不以删除替代。用户新增物体、灯光、活动相机及世界设置保留。
- 首次无活动相机／灯光时可用源相机／灯光作起点，后续由 Blender 管理。直接编辑受管理网格会被下次源几何覆盖；修改器随原对象保留，但未验收任意第三方修改器组合。
- 首次源中心作为毫米锚点，后续中心变化换算为 Blender 米制位移，避免漂移。切换户型时浏览器自动停止推送，插件拒绝向已连接另一户型的文件接收。
- 无新 Furnish 项目字段、保存或撤销通道，不影响空间确认。Blender 修改不反向写回，插件不自动保存工程。可捕获的导入／匹配／更新／删除／元数据应用异常先回滚再暂停：恢复原对象及网格、材质绑定、姿态、可见性、集合归属、同步属性、选择、相机／世界和材质暂存，清理半途导入资源。旧对象和网格到提交后才删除；无引用资源清理失败单列提示，不把已完成提交报成应用失败。Blender 进程崩溃、强制结束、内存耗尽或回滚本身不可执行不在此保证内，应继续正常保存工程。

## 实现与本地数据

`src/ui/blender-sync.js` 维护临时发布开关，`View3D.blenderSyncSignature()` 复用生产三维缓存签名。`src/io/blender-export.js` 添加标识、隐藏状态和实例展开；普通离线导出仍使用可见实体。

`scripts/blender-sync-server.cjs` 接入原 Blender API，验证同步元数据、唯一标识及内嵌资源，提供 SHA-256 不可变版本和原子 latest 索引。浏览器发布限定回环同源和专用请求头；插件使用每次服务启动生成的密钥，只连接本机 HTTP，不接受远程程序、脚本或任意路径。

`scripts/blender-sync-addon.py` 后台线程只下载与校验，主线程定时更新并回报接收状态；关闭文件／卸载停止接收，重复版本不重复导入，清理临时导入对象和无引用数据。

快照位于 `.local/blender-sync/`，暂不自动清理。删除过的精修材质以 Blender fake user 保留，可按需手动清理。完整快照及实例展开会增加大场景的体积和耗时。

## 2026-10-24：0.1.2 与生产部件身份 v2

空调壳体分片／品牌笔画、鱼缸沉木／水草批次与茶几翼板使用明确名称；其余生产模型用固定构造点标签、角色范围及构造时的创建顺序生成组内身份。创建标记仅在运行时用于排序，克隆会保留标记，不写入装修方案，也不把 Three.js 随机 UUID 当持久身份。源码中的固定标签应随代码移动保留，新构造点分配新标签，不能批量重排编号。

角色与构造点内的重复件携带族数量；子节点重排、无关构造点插入、局部移动、整件旋转镜像、保持生成族数量的尺寸缩放及模型克隆不改身份。重复生成器内部增减件时，保留材质模式拒绝数量变化；若需对同一生成器内部的数据列表作等数量的语义重排，应先给列表项明确名称，不能依靠创建序号辨别任意重写后的逻辑身份。新构造器必须纳入覆盖检查，不能把未记录的外部模型推定为已覆盖。

发布器使用 partIdentity=2，服务验证作用域内唯一身份／版本／数量并发布 protocol 2；0.1.1 及更早插件会在导入前拒绝 protocol 2，请更新为 0.1.2。接收器优先匹配身份；旧路径只用于一次性 v1 升级，并核对所属家具／图层、类型、材质槽、顶点与完整拓扑。版本升为2后，不再通过路径把另一身份的旧对象当作相同部件。导入、匹配及应用失败仍沿原事务回滚。

原精修工程若比当前几何版本更旧，直接升级可能被拒绝；这不是丢弃材质的理由。本轮在独立进程中，先用冻结的 v1 导出契约生成同版生产快照并刷新工程副本，再执行严格 v2 升级。v1／v2 快照的二进制几何必须一致，原材质绑定逐项核对，原工程不覆盖；升级后的可用副本与测试中临时分配独立材质的副本分开保存。冻结导出器仅是回归夹具，不由生产应用加载。

## 2026-10-25：生成器内部身份 v3

Live Sync 0.1.3 使用 partIdentity=3 / protocol 3。旧接收器会在导入前拒绝新版协议，需要安装配套 ZIP；v3 工程拒绝 v1/v2 快照降级。

共享模块 `src/core/part-identity.js` 必须在模型脚本前加载，包括独立预览。`produce(site, fn)` 建立同步调用范围；`items(site, [[name, data], ...])` 让固定名称随数据移动，不能在重排后用新下标重算名称；`records` 使用明确业务字段，缺少身份的对象拒绝构建；`range` 的逻辑槽位对应参数角色；`each` 保留回调的逻辑下标；`instances` 将名称、矩阵和颜色作为同一记录重排，再记录实际实例槽位。循环中异常与提前退出均释放作用域。作用域不可跨异步函数。

现有 site / generator / item 名称都是固定源码标识，代码移动时原样保留，新增点分配新名，不能用自动编号重写已有名称。数字数组（例如层板高度）仍表达第几个参数角色，没有新增保存格式或为旧用户数据批量写入字段。厨房、墙面所需 partId 由核心派生，不进入装修方案。重复身份导出直接失败，不回退到按创建顺序猜测。

v2 创建顺序仅用于一次性升级别名，v3 正式键使用完整具名作用域。升级副本先匹配旧别名并核对所属家具／图层、几何、材质槽、数量与世界姿态；不允许将初次升级和等数量互换合并。若旧精修副本有交互姿态变化，先用确认未变的 v2 生产快照在临时副本中记录源姿态，再执行严格升级。源姿态单独保存为 Blender 管理属性 furnishSourceMatrix，并纳入事务回滚；用户锁定的精修姿态仍保留。本轮 4,355 部件的冻结 v2 快照与上一轮留存快照逐字节相同；旧副本仅电视／窗帘 6 个姿态不同，几何全部相同。原始及上一轮精修文件均不覆盖。

升级后，等数量条目互换、辅助构造器调用重排与实例存储重排均按名称匹配；原对象、材质及修改器继续保留。族数量变化仍受保留材质模式约束。创建新生成器时必须扩展覆盖与重排回归，不能假设任意外部模型或重复复用相同名称的克隆已具备身份。
