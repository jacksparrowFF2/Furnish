# 灯光高清预览

2026-11-14。进入三维默认「自动 · 渐进高清」：视角停稳后直接在主画布采样，继续操作时即时响应。独立「高清预览」用于更高采样和PNG下载；「工具 → Blender 渲染」保留基础与精修Cycles。

## 默认渐进观察

`src/ui/progressive-view.js`在主画布上创建不接收鼠标事件的离线预览iframe。停稳250ms后开始，最长边1200px、256采样、8次反弹与OIDN；初始噪点逐渐收敛，完成后停止GPU动画循环。相机变化只更新相机／投影矩阵并重置采样，复用同一BVH，不重打包全屋。浮点尾差经1e-8量化，避免静止视角反复重置。

拖动、缩放或相机动画时暂时露出原生产编辑画布。选中编辑、空间问题高亮、测量和铺贴检查期间保留原辅助线／操作器，结束后自动恢复高清；活动门／窗帘到达保存端态前不取快照。家具、灯光、图层、剖切、吊顶方式或方案变化时销毁过期预览，以新生产GLB重建。晚到的快照、相机和采样消息均按当前场景／视角丢弃，不恢复旧画面。

`View3D.progressiveState/progressiveScene`提供场景签名与纯数值相机快照，沿既有生产构造／GLB导出，无私有网格注入。`progressive-view-core`只集中相机稳定键、视口大小及性能策略，不增加项目字段、数据版本、保存或撤销通道。

性能判断从场景准备完成且视角稳定后的采样消息开始，不把初次打包／BVH／编译耗时当作低性能。持续观察至少12秒，采样速度低于0.25样本／秒，或连续4次GPU帧耗时超过100ms，先降至640px；另一个至少12秒窗口仍慢才回退流畅观察。无GPU计时数据时仍可按实际采样速度判断。相机更新保留已降低的分辨率，不在两种模式间自动往返。

WebGPU不可用、软件适配器、初始化90秒超时或设备错误直接回退，并保留原因和「重试高清」。当前三维观察期间不会不断重试；可显式重试或重新进入三维。「自动／流畅观察」偏好只存在本机localStorage，不写项目。`file://`明确回退；桌面与回环HTTP使用本地依赖。隐藏页面、打开独立高清面板或离开三维会销毁实时iframe，避免两个光追上下文争用显存。独立面板关闭后自动恢复。

本机完整1601真实GPU、三入口、相机复用与编辑辅助验证见[默认观察验收](validation/progressive-view-20261114/README.md)。其他实体GPU／Mac和长期显存压力仍待实测；弱性能分级策略用合成时序边界验证，未冒充低配实机结果。

## 独立出图与失效

进入三维并调整机位、日夜、顶灯开关、剖切和图层，再打开「高清预览」。面板自动生成当前快照；快速为最长边1200px／128采样，高清为1920px／1024采样，均采用8次反弹和本地OIDN引导降噪。完成后下载PNG，并释放该次预览的GPU上下文。

可以继续编辑。改变机位、家具、灯光、剖切、图层、吊顶显示方式或当前方案后，旧预览标记「已过期」，停止运算并隐藏下载入口。点击「重新预览」才重新取景；不会因拖动反复启动昂贵渲染。停止、关闭或离开三维取消预览，晚到的打包／GPU消息不得恢复旧结果。返回三维后可重新预览。

需要可用的WebGPU和足够的显存。桌面程序与回环HTTP支持本地离线资源；直接打开`file://`仍支持原编辑、三维与GLB导出，高清面板明确提示改用桌面或本地服务。设备不可用、设备丢失或GPU验证失败时停止本次预览，保留编辑和Cycles入口。

## 灯光契约

`src/core/lighting-core.js`集中运行时单位、曝光、优先级及生产发光面收集，没有新增项目字段、格式版本、保存或撤销通道。

- 规划规则中的`previewCandela`仍为cd；运行时标记光源按`cd / 683`使用共同RGB辐射量约定。683沿glTF／Blender SPEC的换算约定，不是LED电气光效，也不表示已知实际灯具光谱。
- 泛用面灯、扣板灯和浴霸以生产发光面面积派生亮度：`cd / (683 × m²)`。光追读取生产构造器的局部矩形，复用世界矩阵、完成面底高、旋转和镜像；不另存一份房间或灯位。灯带读取已保存截面与实际修剪后的发光边。当前23个面源包括浴霸的一片发光面，不再用3个点采样代替浴霸面源。
- 快速编辑仍有有界灯光采样：先每件灯具的一个直接采样，再额外直接采样，最后才虚拟反射补光；最多24个光／6个阴影，并按显卡收紧。直接采样请求阴影。较近的反射补光不能再挤掉主灯。
- 高清预览读取全部请求开启且图层可见的真实源，独立于相机附近的快速画面预算。顶灯关闭不关闭原夜景夜灯；隐藏／关闭的灯不能被预算或导出重新点亮。虚拟反射采样和光栅洗顶shader不进入光追，由实际反弹取代。
- 光栅洗顶近似随夜景曝光调整为原强度的1/8；虚拟补光与直接采样统一单位。固定夜景ACES曝光10，弱环境0.015，替代旧曝光1.25；日景曝光仍1.05。环境与日照是预览设定，不是现场测量，不使用自动曝光掩盖灯具变更。
- GLB把标记的聚光／日光重新换回光度值，供Blender SPEC导入；生产发光面保留对应辐射亮度，不再重复导出面灯的聚光近似。导出读取请求状态，不能因快速画面预算把真实已开启光源漏掉。

占位主灯、浴霸与夜灯的未测光通量、灯带亮度仍是规划估值，沿[原规划说明](LIGHTING-PLANNING.md)。这些效果不能替代照度、眩光、IES、红外覆盖或施工验证。快速画面的间接光近似也不能当作最终灯光判断。

2026-11-14床头灯带补充：定制`cove_light`的向上发光面通过显式标记独立于顶灯总开关，自身`lightPreviewLevel=0`或隐藏时关闭；光度为规划估值。通用面灯／米家台灯可选预览亮度，缺失仍100%，保持原顶灯开关。见[床头灯槽契约](COVE-LIGHT.md)。

## 模块边界与离线依赖

主编辑器继续使用现有嵌入的Three.js r160。`src/ui/lighting-preview.js`创建独立iframe，`src/render/lighting-preview.js`在其中使用r187和WebGPU路径追踪，避免混用两套Three对象。公有`View3D.highQualityScene/highQualitySignature`以及`progressiveState/progressiveScene`沿生产GLB快照提供相机、材质和光源；短修订号加相机矩阵用于临时失效，不把完整项目反复发送给面板。

场景BVH在模块worker准备；glTF多primitive可共享BufferAttribute，预览先复制自身几何的属性数组，防止并发传输导致其他任务读取已失效缓冲。此副本处理不改变主编辑网格。仍有快照导出、纹理解码、TLAS与GPU编译开销，拖动时优先显示生产编辑画布，不宣称每个交互帧都完成光追。

本地[依赖清单](../vendor/lighting-preview/manifest.json)锁定Three0.187.0、three-gpu-pathtracer0.0.28、three-mesh-bvh0.9.17和oidn-webgpu0.6.0，共约5.8MB／164个文件，含OIDN权重及许可证。仅改写为本地相对导入，包括worker；运行不访问CDN，不引入应用构建工具。复现脚本与逐文件原始／发布哈希见[供应说明](../vendor/lighting-preview/README.md)。现有打包器复制`src/styles/vendor`，无需新增服务API。

WebGPU显式按设备能力申请最高512MB存储缓冲上限；默认128MB不足以容纳当前约257MB属性缓冲。失败必须退出，不反复提交失效GPU命令。低配／软件适配器不冒充成功；尚未验证其他实体显卡与Mac实机。

## Cycles

基础GLB导出携带同一环境与曝光元数据，基础出图显式SPEC导入，以`log2(exposure)`转换Blender曝光EV；旧GLB缺少元数据时沿历史世界默认值。基础Cycles继续AgX，高清预览使用ACES，所以两张成图不是严格同显示变换的引擎A/B。生产GLB的灯面网格与路径追踪解析矩形也存在薄壳／发光边近似差异。

精修入口继续读取已保存工程，保留材质、布光、世界、曝光、机位和Cycles设置，不用预览环境覆盖精修工程。入口及下载规则见[Blender出图](BLENDER-RENDER.md)。

实际结果、增量范围及未执行项见[本轮验收](validation/lighting-preview-20261114/README.md)。
