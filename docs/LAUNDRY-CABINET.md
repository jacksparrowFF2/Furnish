# 阳台洗衣机柜与定制异形水槽

## 使用

家具库 → **阳台柜** → **洗衣机柜 · 水槽与设备空位**。新建为 1340 × 630 mm，柜体高 900、台面厚 20，总高 920 mm，左侧 700 mm 水槽柜、右侧 640 mm 设备空位。参考用户提供的阳台柜图片；未提供品牌施工规格，这些值仅为可调整的布局初值，价格留空。

详细设计中可编辑模块宽度、增加或删除模块，将模块设为门柜、水槽柜、抽屉柜、设备空位或开放格。开放格带一层层板、没有门板；水槽柜不设普通层板。可取消石英石台面，或设置左后／右后矩形管道缺角。台面外形和柜体板件均真实切去该区域，前沿保持。左右遵循现有柜体的局部坐标与镜像。

洗衣机／烘干机属性 → **洗衣机柜空位对齐** → 选择空位 → **自动居中并对齐前沿**。沿净宽居中、柜体前沿齐平，并同步朝向和镜像，保留设备原离地高度；柜体移动后可再次点击。与现有冰箱定位一样，这是一次定位操作，不新增绑定。宽深高不容纳、尺寸未知、锁定或与管道缺角相交时拒绝，不产生部分移动。取消台面后不再用台面高度限制设备。

水槽另行添加。普通箭牌等成品型号保持原生产模型；**阳台定制水槽（可设异形缺角）** 使用通用 `ksink`，可独立设置盆体的左后／右后缺角。不设缺角时保留历史通用水槽外观；设置后为凹六边形单盆，包含真实盆壁、盆底与龙头，二维图形、三维盆体及宿主台面孔洞共用同一缺角。关联水槽柜后沿用现有随宿主移动及高度同步链路；管道缺角与盆体不匹配时拒绝关联，可调整尺寸或独立摆放。

上方吊柜沿用独立厨房吊柜，可组合开放格。当前洗衣机地柜为一字形，不支持 L/U 或末端薄柜；未新增一体式高柜、叠放承重／五金或厂家通风与安装预留计算。洗烘叠放仍用已有设备离地与连接层功能。空位没有实体侧／背／底板，侧边支撑与台面承重需另作设计。柜体实体检查仍以模块分区减缺角后的保守体积判定，不逐板模拟内部储物空腔。

## 完整组合模板与柜门（2026-10-17）

家具库 → **阳台柜** → **完整阳台洗衣区 · 左洗衣机／右洗衣机**。点击或拖放一次生成 5 件家具：洗衣机地柜、洗衣机、已关联的异形水槽、四门吊柜、双开放格；自动使用独立 groupId 编组，选中任一成员可移动整组。单次撤销删除整套，重做恢复整套；复制／粘贴重建组编号与水槽关联，不与原组混合。组合条目只用于新增，不作为单件家具替换候选。

默认总宽 1340、地柜深 630、台面顶 920 mm。封闭吊柜高 600、底部 1800、顶部 2400、深 350 mm；开放格高 200、底部 1600、深 320 mm。上柜与开放格后侧留 100 mm 服务空间，以配合地柜 100 × 100 mm 后角缺口，均为参考图布局初值。工厂参数集中在 product-rules 的 counter.laundry.area；createLaundryArea 用原生产产品和柜体结构生成成员，不写入新模板身份字段或独立保存结构。

整组属性保留 **切换洗衣机左右位置**，增加 **打开柜门／关闭柜门**，并提供地柜、吊柜、开放格的详细编辑入口。无需解组即可分别编辑柜体。开门操作使用原 kitchen 模块开合与 cabinet 门板状态，控制地柜门和四扇上柜门；开放格没有门。三维场景仍可直接点按单扇柜门。整组开合一次 mutate，支持撤销、刷新、命名方案和项目往返；任一目标柜体锁定时整次拒绝。柜门开启后的障碍提示继续使用现有柜体三维开启检查，不把能开门视为现场无碰撞。

独立三维预览已改为调用同一个组合模板工厂，并增加“打开柜门／关闭柜门”按钮，避免只在预览里拼装另一套参数。`tests/test-laundry-area.cjs` 验证左右／旋转、完整结构、编组复制与关联重映射、恢复往返、开合与锁定，以及真实生产柜门确实向外转动。

完整模板浏览器验收 `verify-laundry-area.browser.js` 已通过隔离 HTTP 与断网 file://：真实家具库点击、一次撤销／重做整套、组属性开合／左右切换、保持门板姿态、刷新、无需解组编辑、真实项目下载上传及 390 px 控件；页面异常 0。已目视检查实际场景开门截图及独立生产预览。证据在 `output/playwright/verification-56a1IX/`；最终 `node scripts/check.cjs` 通过 192 套回归、12 户型、生产语法与本地资源检查，`git diff --check` 通过。实机触屏与施工验收未执行。

## 左右样式切换（2026-10-17）

家具库“阳台柜”新增 **洗衣机柜 · 左洗衣机／右水槽**，沿用同一尺寸及模块配置，通过既有 `flip` 表达左式。原水槽左、洗衣机右样式继续保留。选中洗衣机柜，在属性面板点击 **切换洗衣机左右位置**。

`switchLaundrySides()` 在柜体的局部宽度轴上一次镜像：柜体、显式关联的水槽／灶具、完整容纳于设备空位的洗烘设备，以及同一 `groupId` 的家具一起换位；独立上柜／开放格需要先与地柜编组才随同切换。其他家具不根据距离猜测归属。任一参与对象锁定时整次拒绝。旋转、镜像、离地、模块索引、孔环和尺寸保留原语义，缺角通过整体镜像换边，不修改局部缺角参数。没有新持久字段或保存通道，属性按钮一次 mutate，可整体撤销／重做；复制、刷新、项目与命名方案沿原 flip 与 groupId 链路。

独立完整洗衣区预览也默认显示左式，右下角按钮可切换两种样式。预览中的管道装饰随样式示意换边；实际方案中的建筑管道仍为固定点位，切换后沿用空间核对。

新增核心回归覆盖旋转／已镜像、两次切换物理位置无漂移、关联保持、锁定原子拒绝、组内吊柜、无关设备不移动、左式目录／替换及项目往返。隔离 Chrome 的 HTTP 与断网 file:// 已通过属性按钮切换、整套撤销／重做、刷新持久化、真实项目下载上传与左式目录创建／恢复默认；证据在 `output/playwright/verification-ovyOGn/`。

## 参数与数据契约

- `counter.kitchen.laundry` 为可选对象，包含 `countertop:boolean`（缺失读 true）及可选 `notch:{side:'left'|'right',width,depth}`。缺角宽深为绝对 mm，至少 20；剩余总宽至少 20、剩余柜深至少 150 mm，为模型合法性界限。缩放不缩放缺角，尺寸不足拒绝。新建显式写入台面开关；旧厨房不补写、不转换。
- `ksink.sinkNotch` 为可选同形对象；宽深至少 20 mm，剩余宽深至少 80 mm。新建不带缺角，界面启用时初始示例 100 × 100 mm。盆深 220、盆沿宽 20、盆底厚 12 mm，均是布局假设；产品能力统一位于 `product-rules.js`，不代表定制厂家的要求。
- 使用原 `counter`／`ksink` 类型，完整 kitchen 与产品字段恢复、复制、替换清理、命名方案、项目往返、撤销重做和自动保存沿用原通道，UI 经 `mutate()`。柜体保存在原 kitchen 内；盆体新字段由产品能力校验，跨类型替换清除，同型保留并在尺寸修改时校验。
- 三维宿主缓存读取完整 kitchen 和实际设备孔环；盆体缓存与空间确认补入 sinkNotch。核对规则标记 `kitchen-worktop-v14-laundry`；价格、采购与配色不清空间确认。关闭台面后实体、垂直范围和设备支撑查询同步排除台面，厚度参数仍保留供再次启用。
- 沿用普通脚本和本地引擎，无构建工具、网络依赖或保存格式版本变化。
