# 阳台布花后拖动卡顿：增量验收

2026-11-01。正式方案为“阳台 · 猫砂花架垂直分层”，80件家具、右端架与6盆植物。本次只改运行代码，正式文件未写入；仓库已有工作区JSON修改保留。

## 原因和修复

Node CPU采样显示量距热路径反复调用沙发床等远处模型构造器。FurnitureSolids局部几何LRU容量32、世界实体LRU容量128；原先先重建已淘汰的局部记录，之后才检查仍有效的世界记录。增加不同尺寸的盆栽后，工作集跨过32项，拖动时反复淘汰并重建。

将世界缓存命中检查移到局部缓存之前。保留原键、容量、几何顶点、叶片、板件及空间规则，不用低精度替代实体。世界未命中仍走原生产构造路径。

补测发现三维增量复用根节点时漏掉盆栽mountHeight：移动架体后6盆根高度由800／1500mm变为0。已沿产品garden与安装能力限定恢复原高度，不改其它型号默认值或保存数据。旧代码的生产GLB断言真实失败，作为负例；修复后的生产导出复验另列下方。

[真实桌面连续拖动](desktop-continuous-drag.json)：同一打包EXE、独立工作目录／缓存／端口，正式方案复制后测试，基线f927c4a8，仅切换FurnitureSolids源版本。保持全80件家具及四向净距开启；Alt关闭吸附，每件12个原生鼠标移动处理采样，排除首帧后取中位数。重叠层仅在测试中禁用非目标元素的鼠标命中，不改变实体、绘制或量距计算。

| 对象 | 原处理耗时 | 改后处理耗时 |
|---|---:|---:|
| 花架 | 544ms | 34ms |
| 盆栽 | 506ms | 29ms |

以上为生产pointermove处理时间，不是显示器FPS或端到端输入延迟；未宣称稳定60fps。各次拖动实际改变位置，Ctrl+Z逐件恢复整个家具数组，正式文件哈希不变、页面无异常。

[保留吸附对照](desktop-snapped-drag.json)：机器人531→29ms；花架与盆栽多数采样吸附原位，约10～13ms，不将此组当作连续移动性能证据。
