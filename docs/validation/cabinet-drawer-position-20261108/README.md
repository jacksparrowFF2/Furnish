# 独立抽屉上下拖动定位

2026-11-08，基于311b394e。用户希望玄关柜中部的并列独立抽屉像层板一样上下拖动。本轮新增组件位置编辑，不改变正式方案的尺寸或位置。

## 行为与范围

- 正视／三维斜视均可直接拖动独立抽屉的面板、把手或可见抽盒，上下移动整个组件，含并列抽盒、固定中隔板、面板及把手。原来的开启状态与抽出比例保持，组件不缩放。
- 移动超过5屏幕像素进入拖动，单击沿原模式开合；“选择与编辑”模式的单击只选择。拖动不会额外切换开合，一次拖动只记一条草稿历史。Escape、取消指针和丢失捕获恢复起点。
- 复用10mm网格；Alt临时取消吸附，同高抽屉可对齐。方向键10mm，Shift为1mm。右侧“抽盒底基准距柜底”与画布标注沿同一核心方法编辑，标注点击聚焦数字框；原净宽／净高／净深显示继续保留。
- 限位读取闭合生产板件，对组件每块板与其他板的真实XZ重叠分别计算最近上下边界；同时遵守抽面上下偏移及柜箱高度。允许触及实体边界，不额外推定厂家安装间隙。覆盖柜底的面板不会仅因包络相交就误判为抽盒碰撞。抽出的姿态不改变储物位置的可调范围。

适用`drawerModule`，并列抽屉作为一个组件联动；从柜底叠放的`drawers`及安装在顶端的`slidingTop`保留各自安装语义。不会自动移动相邻层板或门，也不消除原有结构重叠。上下连续拖动限制在当前可调结构区；跨柜重新安装仍沿组件树拖放。完整抽出空间继续由原项目核对判断，本轮没有新增五金、承重或多机构自身干涉求解。

## 数据和生产链

`drawerInfo`读取`CabinetMotion.boards`闭合生产记录，`moveDrawer`只改变已有`bottom`相对位置。草稿拖动、键盘和数字输入复用原`record`／`mutate`保存与撤销，没有新字段、版本或保存通道。组件身份、抽盒尺寸、面板偏移、并列数、饰面及开启状态均保留；`bottom`原本已进入空间配置，因此实体、净高分段、完整扫掠、确认及三维缓存跟随原链路更新。旧实例不自动迁移或补写。

## 验证

- `test-cabinet-drawer-position.cjs`：36组旋转／镜像／离地／闭合及37%／全开组合，共468个实际生产网格姿态；移动后13件组件逐顶点只增加35mm高度，其他板件保持。核对数值板件、世界离地、完整开启高度带、空间输入失效、等于／低于／高于边界、网格及跨箱对齐，以及当前／命名／组件库项目往返和三次恢复无漂移。现有玄关柜上方结构板构成实际阻挡负例。
- `--drawer-position-only`：真实鼠标在正视关闭和斜视40%抽出姿态拖动，核对单击、单步撤销重做、Escape、Shift键、网格／Alt、边界停止、标注跳转、应用历史、保存刷新及390px布局。刷新后从正式生产场景导出GLB，按家具ID和稳定部件键逐件匹配13件组件的实际高度与部分开启位置，容差0.04mm。
- Node增量复验：builder、builder-editing、builder-upgrade、builder-multidoor、builder-open-zones、horizontal-editing、component-parity及改动脚本语法／差异检查。未运行全项目check，未进行不适用的Blender资产重建。

测试使用正式文件固定快照、同一打包EXE的独立工作目录／缓存／端口。正式窗口与用户草稿保持，未提交的项目文件不进入代码提交。相关其他会话没有恢复工作或并发改动迹象，沿用既有协调结论；没有新建临时分支／工作树，历史资产和方案工作树保留。

HTTP、断网file://和隔离正式EXE各通过28项，见[专项结果](drawer-results.json)。保存刷新后逐字段一致，13件正式GLB部件位置通过；桌面原有门抽点击[41项](interaction-results.json)、四类层板编辑[115项](horizontal-results.json)均通过。已实际查看[正视定位](desktop-front.png)与[保持40%抽出后的斜视定位](desktop-open-oblique.png)：抽盒底基准由500mm移至540mm，面板与抽盒仍成组，邻板和整柜尺寸保持。当前正式窗口保留，保存草稿后刷新加载新代码。
