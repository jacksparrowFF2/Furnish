# 模块化升级后的编辑能力复核

2026-11-08。接续二维尺寸手柄修复，按旧编辑入口及现有生产构造核对组件柜。本轮聚焦通用组件编辑和持久化，没有批量升级或改动用户正式方案。

## 本轮补回的能力

| 原有能力 | 缺口与处理 |
|---|---|
| 整组宽／深／高的数字输入、尺寸固定端 | 搭建器右侧增加“整组尺寸与固定端”，同用共享resizeFurniture；固定端沿原resizeAnchor保存。原单箱尺寸入口保留，整组尺寸仍保留板厚、拼缝、踢脚和顶封板。 |
| 一层抽屉单独开合及部分抽出 | 抽屉组原来只存整组状态；逐层控制、画布命中、正式场景点击改为只操作目标层，层高可逐项输入。 |
| 并列抽屉单独开合及部分抽出 | drawerModule逐列沿同一状态接口控制；core.toggle保留lane，生产每列读取自己的状态，其他列及静态隔板不随动。 |
| 全部关闭后重新打开选中部件 | 原按钮只翻转open，零角度／零行程仍在；门、抽屉和活动上盖统一写入实际目标角度／行程。统一抽出设置与独立控制的文案分开。 |
| 从我的家具恢复默认尺寸与颜色 | 原来组件柜type=cabinet被当作内置空柜模板，可能丢结构；现在从原组件库条目恢复完整组件树和颜色，按原尺寸固定端换算位置，保持旋转／镜像和离地。没有明确组件源时跳过，不猜造空柜作为默认。 |
| 显式升级保留独立抽屉姿态 | 可表达的普通柜逐层姿态、玄关置物台并列抽屉姿态进入组件状态；保留原严格结构校验，未扩大未知柜型的转换范围。 |

另一个活动会话负责阳台洗衣机柜／餐边柜入口和柜箱前后对齐；双方已明确文件归属及本轮先提交的顺序，不把该会话尚未交付的能力记为本轮完成。

## 新字段与数据契约

- `drawers.states`按从下到上的层索引记录；`drawerModule.states`按生产lane顺序记录。均为可选的完整数组，每项严格为`{open:boolean, extension:number}`，extension范围0–1，长度须与层／列数一致。
- 新建仍不补写，缺省沿原open／extension统一状态。需要独立状态时才物化数组；单列仍可沿原字段表达。修改数量保留原索引状态，新增项继承原默认值，删除项移除；撤销恢复原数组。非法类型、长度或数值整次拒绝。
- 产品核心集中声明层高、层数、列数和缺省比例；生产构造、数值板件、当前姿态、扫掠、净空共用原组件接口。净空按闭合板件推导，当前开合不改变闭合储物尺寸；真实当前实体和空间签名包含独立状态。
- 保存组件／整组模板时沿specification清除开启状态，重用为闭合姿态；复制现有家具和项目保存保持当前独立姿态。
- 显式独立状态最低版本78。project／repository／cache同步接受78并保留原版本读取；未写入该字段的组件柜最低版本不被强制提升。顶层resizeAnchor沿已有字段和清理规则，无新顶层参数。
