# 型号清单与浮动净距既有失败修复

2026-11-05。修复测试关联和旧测试假设；生产尺寸、空间算法、碰撞拒绝、当前装修方案及保存通道不变。

## 原因与修复

型号清单的五个园艺配置没有关联已存在的专项套件，导致 `test-model-pipeline` 的非空测试断言失败。按产品核心的 `garden` 能力统一复用 `balcony-garden`，阶梯架另复用 `stepped-plant-rack`；保留非空断言，并增加园艺／阶梯配置必须关联相应套件的断言。没有为五款复制测试脚本。

浮动净距旧用例对保存方案的分水器固定执行“右距加20mm并向全局X负方向移动”。现有单件测距已经采用产品局部方向，该实例旋转180°；其0mm参考是橱柜踢脚板，提案位置仍与实体重叠，核心正确拒绝，而旧脚本只等弹窗关闭，最终超时。

- 正向验证复用 `test-manifold-zero-gap` 的四面墙夹具表，统一放在现有 `wall-finish-fixture` 辅助模块。HTTP/file下各执行4种旋转×2种镜像：已知后墙净距110→130mm，按夹具墙法线独立断言20mm位移、距离、原参考及弹窗关闭。贴墙侧向的自随开口边不是固定参考，正向移动使用既有的后墙测量基准。
- 保存方案只作只读输入，在隔离副本中探测提案；与属性编辑器使用同一个局部坐标系。独立检查目标实体／净距，合法提案验证精确移动；空间受阻则验证具体错误、弹窗保留及整个工作状态不变。意外运行时错误仍令测试失败。两种模式均实际命中1个家具实体阻挡并验证拒绝，不把拒绝记成移动成功，也不调整原实例的离地高度或位置。
- 等待条件同时观察“成功关闭”与“错误反馈”，随后严格断言对应结果，避免把正确拒绝变成30秒无信息超时。

资产索引另有[11条陈旧构造引用](asset-index-changes.json)：先前离地补齐已将构造移至 `legacy-furniture`，导航还记录为 `index-inline`。沿既有生成器同步索引，未改模型文件或目录条目数据。
