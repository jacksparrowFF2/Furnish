# 未选中层板可见性修复

2026-11-08，基于12968c21。用户反馈玄关柜未选中时看不到两处层板。MCP读取当前“组件柜试点 · 开放区、门板下延与藏线上盖”，确认固定层板part3位于150mm，开放区part2上边界位于318mm，保存的实体及配置完整。正式窗口有模态编辑，专用截图工具按协议拒绝捕获；保持该窗口及草稿，改用正式文件的固定快照在独立工作目录／缓存／端口验证。

## 原因及修复

预览请求outlines时，临时柜箱先生成活动层板边线，后装入的独立固定板与开放区边界板未生成边线。正视下板件前沿与背板共用木色、没有可见分界，选中染蓝后才容易辨认。修复前相同代码与机位已复现底部两道分层缺失；对应实体一直可在生产场景GLB找到。

v2柜体统一在完成整组构造后生成轮廓，子柜不重复生成。常态场景仅为横向层板添加0.65透明度的淡边线，详细预览沿原outlines请求覆盖全部网格；显式false仍关闭边线。线条按实际板件边界绘制、保持深度遮挡、排除射线命中，所有几何、世界坐标、生产身份及保存参数保持。数值记录器明确不创建装饰线；GLB继续忽略线条而导出真实实体。旧柜型的构造与显示策略不改。

## 验证

- `test-cabinet-layer-visibility.cjs`：三款试点柜、常态／预览／关闭三种策略共54次真实生产板件检查，逐板只有一组轮廓；真实射线指向边线端点仍不抢占点击。几何、身份、输入配置保持，数值记录也不受outlines参数影响。修复前原源0条边线构成实际失败负例。
- `--layer-visibility-only`：HTTP、断网file://、同版独立桌面EXE分别检查未选中正视／斜视、正式场景、150／318mm实体导出、选择／取消选择、保存及刷新恢复。测试只操作隔离快照，源快照哈希断言通过。
- `--horizontal-only --desktop-only`：复验全部四种层板用途的真实点击／拖动、尺寸编辑、撤销、组件复用、刷新及正式场景逐板GLB，确认轮廓不会抢占编辑。
- Node增量：builder、builder-editing、builder-upgrade、builder-multidoor、builder-open-zones、horizontal-editing及改动脚本语法／差异检查通过。改动没有新增实体或持久字段，未运行全项目check；本轮不适用Blender资产建模与回读。

正式方案和用户草稿没有通过本轮测试修改，未提交的项目文件保留。没有其他相关会话恢复工作迹象，沿用既有协调结论，没有重新唤醒已完成会话。本轮不新建分支或工作树，历史资产／草稿工作树继续保留。
