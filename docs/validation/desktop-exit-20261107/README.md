## 已证实的退出路径修复

`desktop/main.cjs`原本把可选MCP桥的启动失败传给整个桌面的启动catch：即使项目窗口已经加载，也会显示“无法启动”并调用`app.quit()`。新增真实生产监听器回归在修复前失败，确认其会调用后台关闭；修复后MCP失败只记录`mcp-start-error`，已加载的桌面继续运行，可从MCP菜单重试。后端连接或页面本身加载失败的原保护保留。没有证据认定11:53的事件就是这条路径。

## 本机诊断与部署

`desktop/diagnostics.cjs`记录`.local/desktop-runtime/events.jsonl`：启动／退出、窗口关闭请求／无响应／恢复、renderer／GPU等子进程退出原因，以及每30秒的CPU与内存工作集。主进程原生或外部强制终止可能来不及写最终事件；需结合最后心跳、系统事件和实际进程状态判断。日志达到1MiB轮换一份，写入失败不阻止编辑和保存；不序列化项目、鉴权token或命令行，不捕获异常来阻止其原有处理。

本机D盘壳先备份至`.local/desktop-exit-backup-20261107`再更新main与diagnostics。诊断已用于当前进程；MCP失败保护用于更新壳后的下一次启动，未强制关闭用户当前窗口来应用它。源码／项目路径、缓存、正常完整性与沙箱保持。

`tests/test-desktop-3d-soak.cjs`只在独立源码／正式文件副本／缓存／端口测试；临时正常完整性运行时在TEMP，结束验证绝对路径后删除。该测试会显示另一个窗口，应提前告知用户；窗口标题标明隔离测试，结束只关闭自己的实例。此次测试实例已正常退出，仅保留正式窗口，不合并两者数据。
