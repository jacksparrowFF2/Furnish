# 阳台柜专项整体检查

2026-11-12。用户要求不只复验最近修复，而是对阳台柜做一次整体检查。范围为两种目录模板、旧方案恢复、当前正式柜体配置及其编辑／空间／保存／生产链；不是整个Furnish仓库全量检查。

## 结论

发现并修复两处实际程序缺陷：

1. 组合内部空间检查原先只把独立原地柜作为待查组，新增柜箱之间、新增柜箱与台面的板件相交可能漏报。现在所有启用的真实组件柜参与组合内检查，使用生产板件的高度裁剪与多边形交叠；正常接触仍允许，关闭柜箱不参与。编辑器提示与项目spaceCheck共用结果。包含组件附属柜的spatialConfig新增派生碰撞规则标记，使旧核对上下文重新评估；价格、配色不导致空间确认无故改变。无新持久字段或文件格式。
2. 台面生成原先把无实际板件的虚拟框架外包也当成柜箱轮廓。非框架柜现在读取实际生产板件，必须有结构板达到该顶标高，并据其真实平面范围生成；空虚拟框不再扩出台面；正例验证实体顶板只有100mm宽时，不按260mm虚框多生成160mm。普通实体柜规则和默认台面基准保持，保存的旧outline不会因加载被重算。

原有21项专项在修复前全过；扩展矩阵才发现以上遗漏。旧生产核心的历史负例均能复现，修复后22项专项全过。证明原先通过不是“没有任何问题”的保证。见[初始结果](baseline-tests.json)、[最终结果](final-tests.json)、[历史负例](negative-controls.json)。

## 当前正式布置仍有三条位置提示

本次检查同时读取当前D盘正式方案并逐板核对，以下是布置问题，不是把正常空腔当实心误报：

- 洗衣机与柜箱组base:1的一块侧板相交。模型中侧板Y为1434–1452mm，洗衣机部分实体最小Y为1447.5mm，交叠约4.5mm。当前洗衣机中心(7080,1745)；只读副本中计算居中吸附候选(7080,1754)，移动9mm后实际板件碰撞为false。[依据](layout-washer-evidence.json)。
- 新增窄柜cabinet1及延伸台面实际板件与墙28／64相交；窄柜平面范围X=7080–7360、Y=2074–2334mm，横跨原阳台边界及墙体，不只是外包相交。[墙体证据](layout-wall-evidence.json)。
- 同一外扩结构触发“家具占地超出房间范围”提示。[当前三条检查结果](layout-issues.json)。

没有自动应用这些布置候选，也没有隐藏墙体／越界／洗衣机重叠提示。正式文件哈希与审计只读副本相同，[保留证明](source-preservation.json)。本次软件检查通过不等于当前摆放位置已全部正确。
