# 组件柜二维整组尺寸手柄恢复

2026-11-08。用户截图中组件柜仍有宽／深手柄，但`cabinet-core.resize`对v2尺寸变化直接报“请在组件搭建器中调整柜箱尺寸”，因此二维拖动与共享数值/MCP尺寸编辑不能生效。本轮让该分支委托组件核心的`resize`，保留原画布吸附、端点固定、错误反馈和历史，不增加另一条拖动或保存通道。

## 尺寸契约

- 宽：各箱原外宽采用同一系数；板厚／外挂收口／拼缝保持。按实际连接树外包宽反解系数，适用左右及上下连接、错位与上柜更宽等分支，目标不是“每箱原外宽×整组外宽比例”。
- 深：各箱原深采用同一系数，保留深浅关系，整组仍以最深箱为准；背板厚、门厚、五金距背等不拉伸，超出原范围时拒绝。
- 高：踢脚和顶封板高度不变，按各箱剩余高度采用同一系数；顶部收口和上下连接间隙保持。内部层板、开放区边界、门段按原相对坐标派生，独立抽屉绝对高度等既有刚性参数不变。
- 保留所有组件、板、门段及门扇身份，门角、抽出比例、安装离地、采购与外观参数不改。柜箱接缝不合并，收口不算作可拉伸板厚。
- 二维宽／深两端与角点固定实际抓取端的对侧，保留旋转／镜像及图纸旋转换算；数值入口保留原中心／柜体左右端偏好。
- 整次操作在副本中完成后通过原结构校验。最小净空、箱体范围、抽屉适配或连接重叠无效时不应用当前采样；已有拖动语义会保留上一合法采样并在结束时提示，完全无合法变化时不新增历史。不是自动解决原布局的墙体／管线／开启干涉。

只修改原箱体w/d/h字段，整组外尺寸重新派生；没有新增持久字段、格式版本、加载脚本、默认值或自动方案升级。空间确认与缓存已包含这些结构输入，沿原规则失效；用户数据不转换。

搭建器顶部的总深读数与宽高统一保留两位显示精度，避免反解后的浮点尾数直接出现在界面；不舍入保存值。

- `test-cabinet-builder-resize.cjs`：132组，包含三种单箱／分格／多箱连接结构、宽深高增减、旋转镜像、刚性参数、安装离地、左右数值基准与两端真实生产pointer监听。原子拒绝、项目当前／命名／组件库、重复恢复和反向恢复尺寸通过。
- 原`test-cabinet-builder.cjs`中的“禁止外部尺寸编辑”断言改为实际可调整；144组合、稳定身份、开合实体和保存链通过。原尺寸轴、双端尺寸180组、均分60组及120真实层板、组件编辑120组、层板编辑、可拆卸板标记／生产提示和组件生产一致性29配置／1170网格回归通过。
- 界面专项`--resize-only`在固定快照的隔离目录、缓存和端口中运行；使用真实鼠标命中尺寸手柄，检查两端宽深／角点、37°旋转／镜像＋90°图纸旋转、原生取消、单步撤销重做、保存刷新。尺寸编辑后实际预览门板关闭深18mm／90°深等于门板宽，再以正式场景GLB按家具ID＋稳定部件键比较逐网格目标边界。
