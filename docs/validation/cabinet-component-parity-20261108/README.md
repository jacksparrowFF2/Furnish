# 组件柜编辑预览与正式三维一致性

2026-11-08，基于2584220f，继续核对层板以外的组件。保留正式方案及当前窗口草稿，使用正式文件固定快照，在独立工作目录、缓存、端口和同一打包EXE中执行测试。没有自动转换或重新保存用户柜体。

## 范围与修复

覆盖组件库15类：柜箱、活动层板、竖隔板、门组、分段门、多段门、开放区、结构横板、独立抽屉、活动上盖抽屉、挂衣杆、抽屉组、踢脚、顶封板和收口板。另含三款现有试点柜、不同深度／分格的拼接，以及左右／对开／上下翻门、木色／素色／玻璃、灯带、并列抽屉和门板下延配置。

1. **轮廓范围不同。** 上轮常态三维仅给横向层板淡边线，详细预览却给全部网格画线，竖板、踢脚、封板和收口板存在相同的混色风险；把手和灯条则被详细预览过度描边。本轮统一实际结构件的淡轮廓，各网格一组，排除把手和灯条。半透明门轮廓随门淡化，线条不抢占射线、保持深度遮挡；显式关闭轮廓及数值记录器保持无装饰线，GLB仍只导出实体。
2. **开孔上下文遗漏。** v2预览转入搭建器时丢掉已有`plan`和`furniture`，导致正式三维有管线开孔，编辑预览和拖放预览却是完整板。两个预览入口现在均传入同一上下文，沿原生产构造器执行真实CSG切割。
3. **半透明门挡住编辑。** 门网格已有`cabinetIgnorePick`，搭建器的点击与拖动射线却未读取。两处命中筛选现在排除该网格，可穿过半透明门选择、拖动层板；正常门仍能点击开合。
4. **不同深度上盖的开孔错位。** 开孔前把上盖恢复至整组最大深度的一半，而非所在柜箱的闭合位置。现在读取生产运动节点的`closedZ`，完成开孔后恢复实际姿态。500／300mm拼接负例中，旧逻辑在真实管心仍有实体，真实射线命中；修复后孔位正确，并随上盖刚性移动210mm。

没有新增持久字段、格式版本或空间规则。未开孔实体、生产身份和数值板件保持，原空间核心本来就在正确闭合坐标切割；本轮让渲染跟随该坐标。灯带亮度、玻璃Alpha近似、独立抽屉的既有联动范围没有扩展。预览使用家具局部坐标，正式三维另叠加户型原点、完成地面及离地偏移，验证时按这些安装基准换算，不把地面高差当作模型差异。

## 验证方法

- `test-cabinet-component-parity.cjs`：29组配置×闭合／37%／全开，比较真实Three生产网格顶点、矩阵、颜色、透明度、深度写入、稳定身份和切割结果。1170个网格、999组结构轮廓及294个被切网格；数值板件、输入数据保持。混深度上盖用真实射线核对孔与邻近实板，覆盖闭合和全开。
- `--component-parity-only`：19组实际编辑窗口（15类、混深度组合及三试点），观察公共生产构造器输出，仅记录而不修改网格。保存全部打开姿态、刷新，再与正式场景GLB按家具ID＋稳定部件键一一匹配，核对264个网格的位置边界、颜色及透明度（边界容差0.04mm）。全关后再核对一次；真实鼠标点击、拖动和撤销半透明门后层板。额外使用公共预览API和相交管线，对照实际CSG实体，验证拖放预览也收到上下文。
- 桌面`--builder-interaction-only`：真实点击多段门逐扇、普通门、抽屉组、独立抽屉和上盖，验证再次点击关闭、保存、应用撤销／重做、刷新及窄屏。通过41项。
- 增量Node：builder、builder-editing、builder-upgrade、builder-multidoor、builder-open-zones、horizontal-editing、layer-visibility、cut-board-motion及改动脚本语法／差异检查。共享开孔恢复影响既有柜型，因此补跑363个生产活动板件及连续切割运动回归；未运行全项目check或Blender资产发布，参数化显示修复不适用资产重建。

初轮测试发现验收样本本身有两处差异：试点原始门已有开启姿态，应先显式全关再记录闭合基准；桌面文件的完成地面为60mm，应换算安装基准。另修正验收脚本未等待退出动画便再次进入三维的竞争，保留失败现场，结束专用隔离窗口后重跑。均只修正测试，没有改用户数据、运行网格或放宽几何误差。
