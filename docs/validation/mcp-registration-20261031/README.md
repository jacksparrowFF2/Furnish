## 失败诊断与边界

早期测试修正了三处夹具问题：原生窗口未显示便请求关闭、端点移除后未等进程释放缓存／实例锁、把Electron异步菜单回调当作同步返回值。都发生在隔离目录，最终整链路已通过；一键启动现使用可见交互窗口，CLI和探测子进程仍隐藏。

注册仅创建缺失的同名条目，不接管其它目录绑定，不改变已有超时／白名单／禁用，也不删除其它服务器。首次显式连接才启用本机启动检查，可从菜单关闭；自动检查失败不会阻止装修编辑。Codex持有真正stdio进程，Furnish只负责本机端点；不会脱离客户端启动一个无人连接的常驻stdio进程。新注册沿官方CLI默认超时，已有180秒设置保持；较长保存等待可按MCP文档调整。

注册和启动无法替代Codex对已经加载聊天的工具重载；本次聊天可见清单仍是旧4工具，独立新连接及注册探测均是11。未测试所有Codex发行渠道、所有Windows权限／防病毒组合，也未改变浏览器与file的注册权限；这两个入口不写Codex配置。源码cmd入口需Node，桌面菜单／完整包入口可用自带运行时。
