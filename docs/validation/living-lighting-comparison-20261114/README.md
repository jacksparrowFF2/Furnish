## 导出缺陷修复

包含厨房和卫生间两片铝扣板时，原导出器将没有显式 `layerObject` 的构件放入同一空建筑scope，两个 `aluminum:backing` 触发真实重复标识错误。现在从生产 `userData.ceiling.id` 派生 `ceiling:<id>` 范围；已有显式层键仍优先，不改变顶面几何、区域ID、产品或项目字段。区域内部真实重复仍拒绝。

`test-blender-part-identity` 新增两片真实生产铝扣板、重排稳定性和同区域重复负例。该套件及 `test-blender-affine`、`test-blender-render`、`test-blender-sync`、`test-ceiling-aluminum` 均通过；真实EXE完整吊顶GLB导出、Cycles导入及保存工程回读也通过。未运行全量检查。

## 发现与边界

- 当前实时预算按相机距离选择采样，同一灯体的虚拟反射灯比主灯更接近相机，客厅主灯虽请求开启却被裁掉。`light-audit.json` 保留真实启用／显示状态。本轮保持生产画面作为基线，预算优先级只在隔离副本做诊断；其局部过曝与暗顶仍说明还需统一单位、曝光和间接光。该问题待后续修复，不能把全部改善归因于新光追。
- 首次WebGPU试跑遇到默认128MB存储缓冲上限；该场景一块数据约257MB，本机支持更高上限，显式申请512MB后完成。移植时须处理能力门禁、显存和低配回退。
- 灯具强度、墙面和材质仍是模型输入；未验证实物配光、IES、照度、眩光、米家联动，未测试移动／编辑后全链路自动失效、长期运行、透明材料全部特性或Mac实机。
- 原图为真实渲染，没有使用生成式图片。浏览器OIDN和Cycles降噪均为渲染管线的标准步骤；保留采样过程与原曝光数据供复查。
