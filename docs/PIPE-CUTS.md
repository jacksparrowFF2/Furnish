# 水气竖管碰撞与柜体避让

2026-10-13。沿用用户指定的竖管占位：默认直径 100 mm，地面至所在房间净高；无房间关联时取项目净高。没有新增家具持久字段。点位位置、pipeDiameter、房间净高恢复后自动重算，切孔不写入原柜体结构配置。

## 共用规则

`src/core/service-core.js` 统一生成 mm 圆柱范围，供家具实体、柜门／上翻门、抽屉和操作空间检查、2D 避让及生产柜体模型使用。实体采用圆与旋转矩形的距离，平面沿用 5 mm 容差；竖向复用 verticalOverlap，面接触免除，未知家具高度保留待核对。检查结果保存 markerId，开启结果同时保存 markerIds，全案定位高亮对应管道。

管道的物理开启检查已改为切孔后的实际板件，覆盖关闭到最大角度／完整行程。生产 buildRaw 为每组运动板件提供铰轴、方向、行程与门扇编号；纯数字记录器执行同一构造器取得矩形／上盖轮廓，按与生产圆柱相同的 64 边切孔和高度分层分解剩余实体，不另写尺寸模板。平开门用圆心反向转动的轨迹到剩余板件的连续最小距离，抽屉用剩余凸分块的完整平移扫掠，因此不会漏掉两端均清空但中途发生的碰撞。铰轴同心孔和已全部切除的板件不再生成虚构碰撞。

上翻门对剩余三维实体与有限高圆柱使用 GJK，并自适应细分全角度区间；用区间最大位移膨胀圆柱证明整段分离，避免仅检查离散姿态。数值接触容差为 0.001 mm；无法在最大位移 0.05 mm 的细分区间或计算预算内证明分离时显示 pending 间隙待核对，不宣称确定碰撞或自由开启。这些是计算精度而非安装预留。64 边切孔的 100 mm 管径径向近似误差约 0.06 mm。圆形旋钮不作为板件；导入 OBJ 缺少运动板件定义时显示待核对。墙、家具、梁仍沿用既有扫掠包络，抽屉站立操作区继续使用偏好阈值，不能因管道孔而豁免人体占位。

空间确认 v3 的 context 包含点位 ID、类型、坐标与有效管径，以及 cut-board-motion-v1 语义标记；规则升级或点位／管径修改使旧确认失效。源图半径、sourceAt、价格和颜色不影响空间确认。属性、柜体草稿和全案共用 spaceCheck。派生板件使用有界内存缓存，运动查询按剩余几何及管道输入缓存；均不写入保存数据。

## 自动切孔

产品规则 `FurnishProducts.serviceCut()` 统一规定能力：参数化柜体，以及现有橱柜台面 counter、浴室柜 vanity。导入 OBJ 不自动切割，继续报实体碰撞；其模型不保证封闭实体。

生产构造器用板件三角实体减去竖管圆柱（本地 BSP 实现 src/render/solid-cut.js）。包含侧板、背板、层板、台面和门／抽屉板，管道在边缘时形成缺口。切割在关闭姿态进行，之后恢复门角与抽屉行程，使孔随板件运动；管道移走后重建完整原板件。孔圆柱采用 64 边外包近似，确保真实圆管不穿入剩余板件，未增加施工预留。

2D 家具图例通过相同位置、直径遮罩显示缺口；3D 主场景与柜体预览共用生产模型。缓存包含管道位置、直径、净高及柜体位置／旋转／镜像。切割只是本工具的自动几何避让，未推导封边、支撑、连接件、板件强度或加工方案。
