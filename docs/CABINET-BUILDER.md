# 乐高式柜体搭建

2026-11-08。第一版完成组件库、拖入吸附、尺寸细节、保存与跨柜复用。入口在家具库「柜体搭建 → 乐高式柜体」，点击或拖入房间会打开空白搭建器；已有组件柜通过原「详细设计」或双击进入。旧柜编辑器也提供「新建组件柜」，另建一件，不覆盖原柜。

## 使用闭环

组件搭建器默认占满应用视口，标题栏“退出全屏／全屏设计”可切换。宽屏左侧仅放组件库，中间是生产模型，右侧并列结构树与属性编辑，三处分别滚动；较窄窗口将右侧两区上下排列，手机宽度改为纵向布局。结构树的尺寸最多显示两位小数并自动换行，保存精度保持原值。

在“三维检查”中，左键单击可见门扇或抽屉会选中并切换开合；多段门按命中的门段和门扇独立操作，普通门组／抽屉组沿其原组语义切换。独立抽屉与活动上盖也走同一核心开合接口。拖动观察、右键及取消指针不会触发开合；正视搭建保留放置与选择，放置期间不误开门。开合沿草稿撤销／重做和原保存链，取消仍不修改原柜。更新姿态或细节保持当前观察方向，尺寸或视图模式变化才重新取景。

1. 拖入空柜箱；之后把柜箱拖到已有箱的左、右、上、下，自动拼接或叠放，后沿对齐。
2. 将活动层板、竖隔板、门组、抽屉组、踢脚、收口板拖入柜箱。绿色生产几何显示可安装结果，目标无效时显示原因，松手不改变数据。也可点击组件卡，再点击安装位置；复制选中部件使用相同放置流程。
3. 点击生产模型或右侧结构树选择对象，在右侧属性中修改。结构树中的现有组件可再次拖动，组件ID保留；新副本及保存组合重新实例化会分配新的箱内ID。
4. 「保存选中为组件」支持单个组件或柜箱，「保存整组到组件库」支持完整组合。它们先进入本次草稿，点击底部「保存柜体搭建」后随现有家具库一起保存；取消整个草稿不写入。后续新柜体的组件库显示已保存项目，可直接拖入。整组也可从主家具库直接放入房间。
5. 柜体编辑沿一次应用 mutate，支持应用撤销／重做；草稿内有独立临时撤销／重做。家具库条目遵循既有目录资源语义，应用撤销柜体不删除已经保存的可复用资源；可通过原家具库管理删除。

门组支持单开、对开、上下翻、最大开角、饰面、颜色、把手及开关；抽屉组支持逐层抽面高度和组开关。活动层板位置及前后退让、隔板位置、柜箱外宽／深／高、板厚、背厚、底板、踢脚高度／内退、收口侧及宽度、连接对象／方向／间距均可编辑。整组安装离地单列。继承默认外观的组件在目标柜中继续继承；单独设置的门色随组件保存。

## 新持久结构

`cabinet.version=2` 保存明确的 `boxes` 组件树，不保存 columns、tiers 或旧模板配置。每箱有稳定 id、w/d/h、thickness、backThickness、bottom、components；首箱为起点，其他箱通过 `attach={boxId,side,gap}` 连接到另一箱。计算位置时检查连接目标、循环、相互重叠与整体尺寸，再派生外包；持久数据不存重复的绝对坐标。

内部组件按 kind 使用严格字段：

| kind | 字段 |
|---|---|
| shelf | id、bay、at、front、back |
| divider | id、at |
| door | id、bay、mode、maxAngle、open；可选 angle、color；handle、finish |
| splitDoor | id、bay、mode、maxAngle、split、lower、upper、handle、finish；可选 color |
| multiDoor | id、bay、segments；每段 id/top/mode/maxAngle/handle/finish/leaves，可选 color；每扇 id/open，可选 angle/maxAngle |
| rail | id、bay、at、depth、size、endGap |
| topClosure | id、height、doorGap |
| drawers | id、bay、heights、open；可选 extension |
| plinth | id、height、inset |
| trim | id、side、size |

`bay` 以左边界隔板ID或 left 识别，不使用易变化的显示序号。`at` 是相对有效净宽／净高的比例：柜箱尺寸变化时内部结构适配，板厚不拉伸；数字编辑用 mm，拖放按10mm设计网格吸附。删掉仍承载右侧组件的隔板、删掉仍连接其他箱的柜箱、重叠箱、负净宽、重叠层板、重复门组及超出有效空间的抽屉均在应用前拒绝。无底时层板定位保留原底板基准，实际空腔／碰撞读真实板件。

`product-rules.cabinetBuilder` 声明版本、24箱／每箱100组件上限与10mm吸附；箱宽150–3000、深150–1200、高200–3200、板厚12–30、背厚0–50，整组不超过6000×1200×3200mm。踢脚、层板退让和收口仍是软件设计范围，不是厂家承重或加工依据。总深为柜体闭合外包口径，凸出把手和开启行程另按实际实体／扫掠核对。

当前所有箱间连接是独立柜箱，保留两块侧板；箱内拖入竖隔板是一块共享隔板。尚无跨柜箱自动并板、转角柜、斜板、任意三维自由连接、五金孔位或结构承重计算。本轮完整闭环的范围不包括这些能力。

## 生产与保存链路

`cabinet-builder-core` 负责组件树、连接、适配、吸附、原子编辑及复用实例化。它派生临时 mm 柜箱数据，调用既有共享板件构造；派生数据不落盘，不为旧柜增加迁移或几何版本开关。生产模型、数字板件、碰撞、二维和正式GLB均消费这条链路；收口实体也由核心输出。

生产部件身份包含柜箱／组件稳定ID；插入或重排层板不重命名原层板。门抽场景点击沿原编辑接口路由到当前组件，柜箱偏移、整组旋转／镜像／mountHeight各叠加一次。正视放置平面与生产模型使用同一坐标，吸附预览以原起点箱为锚，避免组合重居中导致悬停错位。

家具库条目仍使用 store.custom；单组件条目携带严格的 reusable={kind,params} 及一个有效示例箱，参数须与示例组件一致。搭建器拖入时按目标柜腔安装；主家具库点击单组件会进入搭建器。完整箱／组合保存完整树，再拖入时保留内部连接与间距并重新分配ID。库、当前方案和命名方案统一沿原项目／仓库／缓存；含新结构最低v72，其余产品保持原最低格式。两个新增经典脚本随 index 与原离线打包目录发布，HTTP、断网file及同EXE隔离桌面均实测。

完整树及 componentRule 进入空间确认，默认色／饰面和价格不清空间确认，结构与开启状态变化使确认失效。复制保留树，替换为其他类型清理树，重复恢复不重新布局或缩放。现有旧柜和厨房专用构造保留供用户数据使用；新搭建器不自动转换或静默覆盖旧结构。显式升级见下文。

## 重接复用、三类组件与试点升级（2026-11-08）

重接柜箱后，合法连接树的父箱可以排在数组后面。复用先检查整树，再按依赖重分配柜箱／组件ID和隔间引用，最后原子验证组合；不再把数组顺序当作连接关系。根箱的落点、内部连接方向和间距保留。保存选中柜箱、单组件及整组均关闭运动状态，复用后再独立开合。

- **顶封板**与顶部收口不同：柜箱 `h` 是完成高，箱体高=完成高−封板高。封板在全盖门后，门顶按完成顶退让；0延续1mm边缝。层板、挂衣杆相对有效净高适配。高度0–300、门顶退让0–50沿共用产品规则；同箱禁止同时设置顶部收口。增加封板时会改变有效净高；升级已有柜时按原绝对层板标高换算比例，保留原净空。
- **分段门**初期为上下两段，`split` 是完整门范围内的分界比例，界面编辑门缝中心距柜底mm；分界两侧各留1mm边缝，各段实体高至少60mm。两段共用开向／最大角／把手／饰面，各有 `lower/upper={open,angle?}` 状态。场景点击、开角编辑、实体和完整扫掠按段路由，关闭一段不改变另一段。不自动增加中间结构板，不代表五金已选型。
- **挂衣杆**是独立的方截面实体，按隔间净宽扣两端间距；`at` 是杆心相对有效净高比例，`depth` 是杆心距柜背外沿mm。截面16–40（初值25）、两端各0–50（初值2）；默认深度居中。拒绝超出柜腔、穿层板、穿抽屉区域和杆间重叠，层板碰撞读取生产 `shelfPart()`，包含前后退让及接触/穿入边界。方杆几何是布局表达，未含支座、衣架、衣物和承重验算。

修复踢脚组件的内退参数未传到生产实体的问题。`cabinetBuilder.version=2` 覆盖实体／空间确认规则；原有组件树结构保持。仅含上述三种新组件的项目要求v73，基本组件柜仍最低v72；仓库及恢复缓存读取v73并继续保留历史格式。

旧柜详细设计下方提供“升级为组件柜”：先转换为可取消的草稿，保存后才沿一次原mutate替换。MCP `get_furniture_parameters` 提供非持久动作 `cabinetUpgrade:true`，可批量预演、保存并一次撤销；不能与结构替换混用。转换只支持可完整表达的普通 `storage/book` 配置，保留ID、位置、旋转／镜像、底部离地、尺寸、各隔间净宽、层板标高、门状态及采购数据；类型变成cabinet时保留原有效参考价。特殊柜型、上下分箱／专用组合、未知字段及不能表达的独立门扇／多列抽屉状态明确拒绝。转换是一次输入边界操作，新树不保存旧模板、columns或兼容开关。

正式方案副本“组件柜试点 · 猫窝床头柜与囤货柜”已保存：猫窝500×400×500、1箱、净宽464；囤货2395×350×2350、3箱、各净宽762.333mm，箱体2300、门顶2340，原层板标高与六扇90°开门状态保留。逐板与完整扫掠对比一致，24件柜内用品的四向及上下净距一致，其他164件家具不变；原命名方案保留v1柜。空间核对仍有原有第二层卷纸重叠提示，未移动物品或自动确认。[本轮验证](validation/cabinet-builder-upgrade-20261108/README.md)。

## 多段门与逐门扇开合（2026-11-08）

本阶段更新上一轮“限上下两段／组开合”的边界。新建“门组”“分段门”“多段门”分别生成1、2、3段 `multiDoor`，统一使用独立门扇；已保存的普通门／上下门保持原数据，可点击“转为多段门／逐扇编辑”显式转换。独立门组及分段前面板仍通过共享生产门构造，不增加内部结构板。

`segments` 从下到上连续排列，允许1–12段。每段的 `top` 是门组有效范围内的累计比例，最后一段严格为1；有效范围扣除下方抽屉，顶部保留门顶退让。界面以距柜底mm编辑顶缝，每段面板扣两端各1mm边缝后至少60mm。可“拆为两段”或移除此段让相邻段填满；既有未移除门段／门扇的ID、状态及限位保留。新拆出的上段分配新身份并关闭。

各段独立选择开向、默认最大角、把手、饰面和颜色。对开段两扇，其余左开／右开／上翻／下翻段一扇；每扇独立 `open/angle`，可覆盖最大角或恢复继承本段1–180°限位。修改一个当前角度不改变其他门扇；降低限位只夹紧该扇，关闭不缩小最大开启核对范围。场景点击按门段与门扇路由，预览点击可定位该扇的编辑项。可统一打开／关闭全部门扇，各扇停在自己的最大角。软件铰轴／方杆和角度能力仍不是厂家五金、连杆或承重参数。

柜箱、组件、门段、门扇的ID在整组内唯一；复制／库复用重分配全部层级的身份，移动保留身份。规格与组件库统一关闭所有门扇，但保留限位、分段和外观；当前姿态沿原项目／命名方案／撤销／缓存保存。含 `multiDoor` 的数据最低v74，基本v2及上一轮组件保持原最低格式；`multiDoorRule=1`仅加入多段门空间输入，不无故使其它组件柜确认失效。新增脚本数量不变。

显式升级扩展到普通 `wardrobe-hanging`，从原生产接口读取门段、逐扇实际姿态／限位和挂衣杆；单列抽屉的一条lane可转换，不能完整表达的多列／分层抽屉、特殊构造和未知字段继续拒绝。新树不保存旧模板、columns、doorSections或兼容开关。

正式副本“组件柜试点 · 次卧衣柜多段与逐扇开合”保持1637.5×630×2450mm、两箱各818.75外宽／782.75净宽、594闭门口径净深、2400箱体＋50封板、2440门顶、原层板／三根挂衣杆及48件生产板件。保留原上下两段共八扇，左柜下部两扇90°开启，其余关闭；第二箱保留左150°／右90°限制。实际分别试开37.5°／关闭和120°／60°后恢复原姿态并持久保存；三段及更多的编辑另在隔离副本验证。其余165件家具不变，原方案保持v1衣柜。原抽屉前800mm操作区被单人床占用的提示仍待实际布置调整。[本轮验证与截图](validation/cabinet-builder-multidoor-20261108/README.md)。

## 通用开放区、门板下延与活动上盖（2026-11-08）

`openZone` 是隔间内的开放区域，`from/to` 按扣除顶封板后的箱体高保存比例，界面使用距柜底mm。组件明确拥有上下边界板、侧开口、侧开口后沿、背板连续或缺口、板前沿退让和可选灯条；侧开口仅能落在箱体外侧隔间。边界板可延伸一个侧板厚到开口外沿，背板分段与结构板的接合分别表达。`panel` 是可独立拖入的结构横板，按箱体高保存板底比例，可选门面覆盖宽度及两侧留缝；活动层板继续使用原 `shelf`。开放区轮廓只供拖入和选中显示，实体和柜内净空继续来自生产板件，空区标记不豁免碰撞。

`multiDoor.range` 指定门组原上下缘占完成柜高的比例，`drop` 为额外向下延伸的mm，默认0。一个隔间可有多个互不重叠的门组，因而能在门组之间保留开放区。门扇实体仍扣每端1mm边缝，独立分段／逐扇开合保持；正下延门组的开启核对在实体上下缘各保留1mm边界余量，延续原下延门的保守核对口径。下延不改变结构板、底板或隔间净高。

`drawerModule` 独立定位单层抽屉，底部按箱体高保存比例，层高、抽盒上退和抽面上下偏移均为mm；支持1–8个并列抽屉。同一组件的并列抽屉联动，尚未提供逐个并列抽屉的独立姿态。`slidingTop` 将活动上盖、抽面、底托和两侧板作为同一刚性抽拉机构，沿前向移动柜深的70%，支持0–1伸出比例及0–150mm范围内的后部藏线空隙。上盖保留原缺口多边形；托盘底板12mm、底部上移12mm、侧板上移24mm／顶退40mm为现有模型的布局参数，不是滑轨加工、五金或承重依据。添加上盖时移除固定顶板，补齐其他隔间的固定顶板并形成背部开口，保存单组件时连同必要的开口关系验证，跨柜拖入重新创建这些关系。

新组件、显式门组范围／下延或固定顶板开关最低格式v75；当前、命名方案、组件库、导入校验、复制、撤销重做及离线缓存沿原链路。新能力使用 `openZoneRule=1` 空间语义；其他组件柜仍保持原输入。价格／颜色／饰面不额外清除空间核对。升级后的树只含柜箱和组件，不保存 entry、template、columns 或旧配方开关；旧柜只在用户显式升级动作中一次转换。当前转换限经过验证的18mm、无踢脚玄关置物／电视柜配方，复杂层抽屉、未知覆盖等不能完整表达时拒绝。

正式副本“组件柜试点 · 开放区、门板下延与藏线上盖”（dmw7dk6f0）升级970×350×2350玄关置物台、600×350×2350宠物餐饮柜、2505×350×350电视柜。净空、现有物品及163件其他家具保持，原方案仍保留；原8条空间问题不因模块化消失。[验证、边界及试开证据](validation/cabinet-builder-open-zones-20261108/README.md)。

## 通用编辑能力补齐（2026-11-08）

搭建器复用原尺寸投影、标注避让、显示选项和层板吸附算法。新核心 `measurements`／`shelfInfo` 读取 `CabinetMotion.boards` 的闭合生产板件，在各柜箱局部mm坐标中推导隔间净宽、板面间净高和分高度净深，不把门当前打开后的范围当作储物净深。净深扣实际背板与闭合面板，工程门缝每端1mm保守归入门段范围；开放背部／无底板／无顶板使用名义柜箱边界并标注开放，不能据此推断实体、承托或安装余量。层板实体深度另列，不与储物净深混用；侧开口净宽表示原结构跨度。抽屉上方按抽盒实体限界，抽盒内部、衣物／五金所需空间仍需专项核对。

选中活动层板后可直接拖动调高，输入板底距柜底、上方净高或下方净高；标注按钮跳到同一数字属性。拖动不越过相邻实际板件，保留40mm软件编辑净高；该值沿原编辑器规则，不是厂家或施工要求。竖隔板可直接横拖或输入左右净宽，在总外宽不变时改变相邻两格，最小净宽100mm；单隔间输入净宽时调整该柜箱外宽。隔板移动继续适配所属组件，稳定ID不变。均分仅调整当前隔间已有层板，分别在固定结构板划分的区域内计算净高，不越过固定板或抽屉，失败时不保留部分结果。

默认10mm吸附，沿用原层板相邻对齐逻辑，并支持相邻柜箱层板标高对齐；可关闭吸附或按Alt临时关闭。方向键移动10mm，Shift加方向键移动1mm；拖动中Esc恢复起点并保持窗口打开，一次完整拖动只生成一次草稿撤销。画布内Delete删除所选组件、Ctrl+D准备复制后放置；撤销恢复组件身份。柜体名称、默认颜色和离地高度也进入原草稿历史，离地参与草稿空间核对，保存后仍沿原应用 `mutate`。没有新增持久字段或格式版本。

“显示与编辑选项”提供选择编辑／开合预览、当前／全部标注、标注开关、正常／隐藏／半透明门板、吸附开关、全部打开／关闭和草稿空间核对。自动门板模式在正视结构编辑时隐藏门板，选中门组时显示；三维正常显示。选择编辑模式只选择门抽，开合预览保留原真实点击行为；可点击标注避让活动面，防止遮挡门抽点击。全开／全关调用各机构原开合规则，空间核对只读取草稿，不写正式家具或确认记录。

原编辑器中的特殊模板和厨房专用控制不回填到v2树；开放区、门板下延、顶封板、分柜踢脚、挂衣杆等沿对应组件属性编辑，不能完整表达的特殊旧柜继续拒绝静默转换。任意折叠／推拉连杆、并列抽屉逐个独立姿态、五金和载荷校验仍不在本次能力内。[编辑对照及验收](validation/cabinet-builder-editing-20261108/README.md)。

## 层板编辑与结构用途统一（2026-11-08）

活动层板、独立固定层板（原结构横板）、开放区上下边界层板共用 `horizontalSelection`／`shelfInfo`／`moveShelf`／`editBoardShape`。选择键为柜箱ID、组件ID，以及边界层板的 `board:lower/upper`；边界角色是临时选择身份，不存入家具。生产网格标记同一角色，结构树在开放区下列出可单独选择的上下边界，画布点击只选中命中的板件。右侧统一为“层板”属性，另列结构用途。

四种用途都有板底位置、上下净高、实体板宽／板深、前后退让、两侧留缝、左右延伸、门面宽度覆盖和所属隔间编辑，支持同一套拖动、方向键、吸附、尺寸跳转、撤销重做、复制和保存复用。实体板宽通过对称侧缝调整，20mm每侧为现有模型编辑范围；左右延伸和门面覆盖仍为显式结构选项。所属隔间净宽调整继续影响该隔间内组件，板厚继续随柜箱；不是独立修改某一板的厚度。活动层板仍有原40mm编辑净高，固定／边界层板允许与相邻结构板接触；界面字段一致，合法范围按结构用途和实际相邻板件推导。

界面前后退让统一量自柜箱外沿。活动层板保存的 `front/back` 仍是实际闭合面板／背板内面后的附加退让，由共用接口换算；旧数值不重写。固定层板沿原绝对退让，边界前退沿原 `lowerFront/upperFront`；新增可选 `lowerBack/upperBack` 为绝对后退，缺失时继续随箱体背板内面。活动层板可选 `extendLeft/extendRight/face/edgeGap`，边界板通过可选 `lowerShape/upperShape` 保存这四项的局部覆盖；缺失时沿原开放区侧开口延伸设置。共同形状范围由product-rules声明，实际宽度同由生产矩形接口推导，活动层板的宽度／中心通过原生产构造器的临时参数传递，记录器与显示／导出同源。

移动开放区下边界板按 `from=(板底+板厚)/箱体高` 换算，上边界按 `to=板底/箱体高` 换算，关联侧开口、背板分段及上沿灯条随所属边界联动；另一块边界、门组保存范围和抽屉定位保持。删除仅取消该边界板，保留开放区；复制／保存选中边界板生成具有相同形状的独立固定层板，保留开放区整组复用的原入口。固定及边界层板仍作为均分活动层板时的结构分界，不因可编辑而自动参与均分。

净高分段修复：抬高或位于中部的抽屉按闭合抽盒实体占据的高度带分隔，不再把最高抽盒上沿视作整个隔间的底面，因此保留下方层板与开放区净高。侧缝／局部缩宽层板仍作为隔间分层的保守高度边界；物品是否可放置继续由真实板件碰撞判定，不能仅凭这一列净尺寸推断局部通行或承托。

只有使用新增活动板形状或边界后退／形状字段才要求v76；默认配置及旧固定板继续沿原最低版本。当前、命名方案、组件库、项目、仓库与离线缓存同步识别76并保留历史读取。新字段进入原组件空间输入；没有新保存或撤销通道，也没有自动迁移用户方案。未编辑的试点柜生产板件保持，108块真实试点板在旋转／镜像／抬高情形下验证；[验收和截图](validation/cabinet-horizontal-editing-20261108/README.md)。

## 层板常态可见性（2026-11-08）

修复固定层板和开放区边界板在未选中正视预览中与背板混色的问题。原边线只在临时柜箱子构造中添加，随后装入的独立组件没有经过该步骤。组件柜改在所有部件组装完毕后统一完成轮廓：常态三维为全部横向层板提供淡边线，详细预览的 `outlines:true` 覆盖全部板件且各网格只生成一次；显式false关闭边线。边线保持深度遮挡并排除射线命中，不改变实体、尺寸、材质分区、开合、项目格式或空间确认。数值记录器明确关闭装饰边线，生产GLB继续只导出实际实体。玄关柜板底150mm的固定层板及318mm的开放区上边界板经未选中正视、斜视及正式场景检查。[同机位前后与验证](validation/cabinet-layer-visibility-20261108/README.md)。

## 全组件显示与开孔一致性（2026-11-08）

继续核对全部15类组件及门向／饰面／拼接变体。常态和详细预览统一结构件淡轮廓，竖板、踢脚、顶封板、收口板及活动面板也可辨认；把手和灯条不描边，半透明门轮廓随门淡化。搭建器和拖放预览传递已有方案／家具上下文，复用正式三维的真实管线开孔；点击和拖动射线读取半透明门的忽略标记，可直接编辑内部层板。不同深度组合上盖在自身运动节点的闭合位置开孔，再恢复姿态，不再使用整组最大深度。

无新字段或保存格式；未开孔几何、板件身份、数值实体、离地及原保存／撤销链保持。29组配置的生产顶点与姿态、实际编辑窗口与正式GLB、保存刷新及逐类真实点击开合见[验证与边界](validation/cabinet-component-parity-20261108/README.md)。玻璃仍为原Alpha近似，照明／五金和多机构自身干涉能力没有扩展。

## 独立抽屉上下定位（2026-11-08）

独立抽屉可在正视／三维画布中上下拖动，抽盒、面板、把手及并列中隔板整体移动，原开启状态和抽出比例保持。5屏幕像素区分单击与拖动，单击继续沿显示／交互模式开合；一次拖动一条历史，支持Escape取消、10mm吸附、Alt取消吸附、方向键及Shift精调。原“抽盒底基准”数字框与可点击标注共用`drawerInfo`／`moveDrawer`，净空标注保留。

可调范围按闭合生产板件的逐板XZ交叠与最近上下结构边界计算，并覆盖抽面上下偏移；不自动移动邻板。只更新原`bottom`，无新字段／格式，生产实体、净高、完整扫掠、缓存和保存复用跟随既有链路。适用独立抽屉（含并列组件），固定从柜底叠放的抽屉组和顶端上盖安装语义保持。[实体、交互与保存验证](validation/cabinet-drawer-position-20261108/README.md)。

## 其余组件定位与尺寸（2026-11-08）

挂衣杆可直接上下拖动、修改实体杆长、距背和截面；开放区支持空腔选择及整区移动，净底输入整体平移，净高／上界输入调整上边界，独立边界板编辑保留。多段门在“选择编辑”下可整体拖动，新增覆盖高与可拖动门缝标注，单击标注定位数字框；“开合预览”保留点击开门、拖动转视角，逐扇姿态及限位保持。踢脚、顶封板和收口板沿安装基准拖动调整高／宽，尺寸变化沿原结构链重建。

核心编辑描述和尺寸范围由预览、数字输入共用，移除界面重复换算；原层板、隔板、抽屉方法继续委托。复用原历史、键盘、吸附和保存，只改已有字段，默认门组实际移动后才补既有range，不新增格式或自动转换用户柜体。全15类能力矩阵、锚定组件边界及生产／三入口／保存复用验收见[专项记录](validation/cabinet-component-edit-20261108/README.md)。

## 均分入口与结构尺寸（2026-11-08）

画布工具栏下方常驻“均分”：左右分格、柜箱等宽、活动层板、固定层板。左右分格扣除外侧及竖隔板板厚后等净宽，外宽保持；柜箱按外宽（不含收口）在“当前横排／整组柜箱”范围均分，所选宽度总和、板厚、深高、拼缝和连接保持，操作前显示整组外包宽度变化。固定层板包含结构横板和开放区边界，活动层板及非参与结构不动，在各自结构区中扣板厚均分净高；灯带和开口跟随边界。

所有操作先在副本中整体分配再验证，净高不足或缩窄导致子组件装不下时不产生部分修改。沿原草稿／应用历史，保存与复用只更新已有隔板、板位置及箱宽字段，无新格式。真实板件尺寸、范围、40mm阈值、门扇端态、保存刷新和并行收尾见[均分验收](validation/cabinet-equalize-20261108/README.md)。

## 可拆卸层板标记（2026-11-08）

组件柜中活动层板、结构横板以及开放区上下边界层板可逐板勾选“可拆卸（需要时可取下）”，结构列表及所选板宽标注显示标记。结构用途与拆卸能力独立，固定结构板不会因此转成参与活动层板均分的层板。标记后以25%不透明度显示，独立材质不污染共享材质缓存，原安装尺寸及门抽扫掠不变；默认仍检测碰撞。独立“不参与碰撞检测（模拟取下）”开关通过生产板件元数据排除本板的solidParts，测距和全案碰撞共用。尺寸标注保留原安装位置，不自动合并标注格高。取消可拆卸会清除本板碰撞豁免。需要从设计中实际取下时沿原“删除选中”，开放区仅删除所选边界。撤销可恢复原板，本轮没有独立“已取下／装回”的库存状态。

字段：shelf/panel 的可选 `removable:boolean`／`ignoreCollision:boolean`，openZone 的可选 `lowerRemovable/upperRemovable:boolean`／`lowerIgnoreCollision/upperIgnoreCollision:boolean`。碰撞豁免true只允许对应可拆卸为true，默认检测碰撞。新建不补写；旧缺失按产品规则 `horizontal.removableDefault=false` 显示未标注，不推定旧活动层板具备可拆能力。显式错误类型拒绝；整箱／整组／单组件复制和复用保留标记，边界板独立保存为panel时转换对应单板标记。替换产品沿原清理整个cabinet字段，不新增顶层字段或保存通道。

最低项目／工作区版本77；缺失仍保持原最低版本，保留v72–76及更早恢复。缓存入口v77回读历史候选。可拆能力不参与 `spatial()`，不会清除空间确认；碰撞豁免及实际删除改变空间签名。全cabinet的既有显示缓存可以随编辑正常重建。标记只表达设计意图，不代表连接五金、承重、拆卸顺序或取出路径已经核验。旧模板需显式升级为组件柜后使用，不自动改变正式方案。

验证见[可拆卸层板验收](validation/cabinet-removable-20261108/README.md)。
