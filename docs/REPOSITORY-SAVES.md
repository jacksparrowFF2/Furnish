# 仓库设计文件与跨电脑使用

## 本地正式文件与历史备份（2026-10-30，取代下文固定仓库路径的默认用法）

正式数据可以与程序目录分离。在“保存／导出 → 保存位置与历史备份”填写完整文件夹路径并选择“保存到此位置”；本地服务或桌面版会复制当前正式文件、有效历史备份和迁移／冲突恢复副本，保存本机配置并刷新。源文件和原历史不删除。目标已有不同项目时拒绝切换，未知格式、损坏目标或写入失败也停止迁移，不按文件时间推定覆盖。也可运行 `node scripts/configure-storage.cjs "D:\1601装修\Furnish项目"`，随后重新启动原入口并刷新；`--status` 查看配置。

本机选择记录在程序目录的 `.local/storage.json`，不入 Git；尚未选择时兼容原 `projects` 目录。当前用户数据迁移至 `D:\1601装修\Furnish项目`。不同程序副本的配置各自独立；多个副本若指向同一数据目录，共用该目录的保存锁和内容修订比较。同一源码目录的其他运行中服务发现配置改变后拒绝旧路径写入，须重启，不静默写回旧目录。

所选目录结构：

- `workspace.furnish.json`：全部户型、当前工作槽、命名方案、自定义库及项目内附件的正式文件，沿用原格式、校验和缓存仲裁。
- `backups/*.furnish.json`：每次正式内容变化，先将上一份有效文件按原始字节写入历史，再原子替换正式文件。备份失败则不覆盖。相同内容不重复备份。保留最近 50 个版本，以及最近 30 天每天最后一个版本（天界按 UTC），超过策略的受管历史会自动清理；其他文件不清理。历史条目显示备份生成时间，不代表方案最初编辑时间。
- `recoveries/*.json`：迁移及冲突原始工作区，去重保存且不自动淘汰。旧 `.local/furnish-recovery` 也仍可读取，换位置时复制保留。
- `damaged/*.json`：明确从历史恢复损坏正式文件时，先保全损坏原文，不自动淘汰。

保存菜单显示真实路径、最后成功写入时间，以及仍在等待落盘或保存失败的状态。临时写入错误可在设置中重试；内容／路径冲突须刷新处理，不能用重试绕过。历史支持下载完整工作区及“恢复此版本”：恢复替换全部户型和命名方案，不等同于单户型项目导入；先保存当前编辑和恢复副本，再备份当前有效正式文件，最后恢复并刷新。损坏文件可以显式从有效历史恢复，恢复后浏览器旧缓存不得再次覆盖用户选择的版本。

保存响应丢失或超时时，页面读取正式文件核对：内容修订精确等于本次尝试才确认成功，等于原基准可继续保存，其他修订仍是冲突，不按时间覆盖。暂时故障最多自动重试3次（1.5／5／15秒间隔），只续写最新快照；格式校验失败和真实冲突不自动重试。继续编辑不会隐藏具体失败原因。工作区读取超时60秒，正式写入／位置迁移／恢复120秒；超时不等同于磁盘一定未写入。

直接打开 `index.html` 继续使用 localStorage／IndexedDB 和手动导入导出，不请求文件接口，也不自动读取所选目录。设置入口会说明须通过原启动脚本使用正式文件保存。普通静态服务缺少接口时仍明确显示文件保存不可用。此改动无新项目字段、不升级格式、不改变 mutate／撤销重做通道。

同盘历史用于版本恢复，不能抵御整盘损坏；建议将整个项目目录纳入另一块磁盘的备份。迁移前仓库文件保留以便找回，但后续外置设计不随代码 Git 推送；切代码分支也不会替换外置设计。旧文件不要当作最新项目继续并行编辑。当前无跨设备自动同步、并行布局自动合并或目录浏览器；用户可粘贴完整保存路径。进程中断留下的锁仍需确认无写入进程后处理。

通过 `start-furnish.cmd` 启动后，所有已保存户型工作槽、命名方案、自定义家具库和项目内附件，统一自动保存到 `projects/workspace.furnish.json`。文件包含当前户型编号，不包含本机恢复历史、撤销栈、语言、主题和面板偏好。已有独立 `.furnish.json` 备份继续可用。

## 日常使用

1. 开始编辑前用 Git 拉取更新，然后启动／刷新 Furnish。
2. 编辑、撤销、重做均沿原保存链路。浏览器立即缓存，停止编辑约 650 ms 后写仓库文件。页脚“已保存到仓库文件”代表文件写入完成，不代表已提交或推送。
3. 结束时检查设计文件改动，自行 Git 提交和推送。另一台电脑 clone／pull 后启动即加载设计。
4. 同一工作区尽量只在一台电脑、一个窗口编辑。文件发生外部更新时旧页面停止覆盖；刷新后从“保存／导出 → 本机恢复副本”选择需保留的编辑。

不自动执行 Git 命令，不自动合并设计冲突。设计文件与代码处于同一分支；切换分支也会切换设计。文件含户型和项目资料，提交前按仓库可见范围检查内容。

`.gitattributes` 对工作区文件禁用 Git 自动内容合并，仍保留文本差异；两边同时改动时需要手动选择或保留双方完整文件，避免把两个布局悄悄拼接。

## 首次迁移与恢复

没有仓库文件时，先保存 localStorage／IndexedDB 中不同的工作区副本，再将时间较新的有效工作区写入文件。这仅沿用旧缓存之间的时间排序，不用时间戳覆盖已有仓库文件；另一个缓存的独有内容保留在恢复副本中供按户型导入合并。

已有文件时，缓存 `_repository` 元数据记录确认过的文件版本与加载后的缓存指纹，仅保存在浏览器：

- 缓存与文件相同，或缓存自上次加载后没有编辑：加载仓库文件。
- 文件仍是缓存的基准版本，而缓存有尚未写入的编辑：先保存恢复副本，再续写本机编辑。
- 文件和缓存都改变，或旧缓存没有基准信息：保留不同缓存，加载仓库文件，不自动覆盖。

版本使用稳定 JSON 的 SHA-256，忽略顶层缓存时间戳和本机版本标记，保留所有设计字段及数组顺序。恢复继续运行原工作恢复与生产模型链路。未知版本、数据校验失败或未解决的 Git 冲突会暂停文件保存，保留文件和缓存。

恢复副本位于 `.local/furnish-recovery/`，内容去重且不入 Git。界面可下载整个工作区副本，或按户型沿原项目导入链路载入（包括命名方案及家具库合并）。整个工作区副本不是旧的单项目格式，不能直接用单项目导入按钮加载。暂不自动淘汰磁盘恢复副本，避免丢失首次迁移中的未识别编辑；目录可能随长期冲突增长。

清除浏览器本机数据不删除仓库文件及磁盘恢复副本，刷新会重新加载仓库设计。浏览器撤销栈和历史恢复点不随克隆迁移。

## 写入与兼容边界

服务只监听 `127.0.0.1`。接口限制本机同源、固定目录，不接受任意路径。写入共用项目校验和基准版本比较，通过同目录临时文件、fsync、rename 替换；磁盘互斥锁防止同仓库多个服务同时保存。进程被强行终止可能留下 `projects/.workspace.lock`，确认没有服务写入后才可移除该锁。临时文件和锁不入 Git。Git 不参与此锁，编辑期间不要同时切分支或更新文件。

普通静态服务没有接口时明确提示文件保存不可用，浏览器仍按原链路缓存。`file://` 保留浏览器缓存及手动导入导出，不访问仓库接口，也不自动加载仓库设计；自动迁移请使用启动脚本。工作区接口上限 64 MB，单项目导出上限仍为 30 MB；附件保留原项目限制。
