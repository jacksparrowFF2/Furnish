# 仓库设计文件与跨电脑使用

通过 `start-furnish.cmd` 启动后，所有已保存户型工作槽、命名方案、自定义家具库和项目内附件，统一自动保存到 `projects/workspace.furnish.json`。文件包含当前户型编号，不包含本机恢复历史、撤销栈、语言、主题和面板偏好。已有独立 `.furnish.json` 备份继续可用。

## 日常使用

1. 开始编辑前用 Git 拉取更新，然后启动／刷新 Furnish。
2. 编辑、撤销、重做均沿原保存链路。浏览器立即缓存，停止编辑约 650 ms 后写仓库文件。页脚“已保存到仓库文件”代表文件写入完成，不代表已提交或推送。
3. 结束时检查设计文件改动，自行 Git 提交和推送。另一台电脑 clone／pull 后启动即加载设计。
4. 同一工作区尽量只在一台电脑、一个窗口编辑。文件发生外部更新时旧页面停止覆盖；刷新后从“保存／导出 → 本机恢复副本”选择需保留的编辑。

不自动执行 Git 命令，不自动合并设计冲突。设计文件与代码处于同一分支；切换分支也会切换设计。文件含户型和项目资料，提交前按仓库可见范围检查内容。

`.gitattributes` 对工作区文件禁用 Git 自动内容合并，仍保留文本差异；两边同时改动时需要手动选择或保留双方完整文件，避免把两个布局悄悄拼接。

## 首次迁移与恢复

没有仓库文件时，先保存 localStorage／IndexedDB 中不同的工作区副本，再将时间较新的有效工作区写入文件。这仅沿用旧缓存之间的时间排序，不用时间戳覆盖已有仓库文件；另一个缓存的独有内容保留在恢复副本中供按户型导入合并。

已有文件时，缓存 `_repository` 元数据记录确认过的文件版本与加载后的缓存指纹，仅保存在浏览器：

- 缓存与文件相同，或缓存自上次加载后没有编辑：加载仓库文件。
- 文件仍是缓存的基准版本，而缓存有尚未写入的编辑：先保存恢复副本，再续写本机编辑。
- 文件和缓存都改变，或旧缓存没有基准信息：保留不同缓存，加载仓库文件，不自动覆盖。

版本使用稳定 JSON 的 SHA-256，忽略顶层缓存时间戳和本机版本标记，保留所有设计字段及数组顺序。恢复继续运行原工作恢复与生产模型链路。未知版本、数据校验失败或未解决的 Git 冲突会暂停文件保存，保留文件和缓存。

恢复副本位于 `.local/furnish-recovery/`，内容去重且不入 Git。界面可下载整个工作区副本，或按户型沿原项目导入链路载入（包括命名方案及家具库合并）。整个工作区副本不是旧的单项目格式，不能直接用单项目导入按钮加载。暂不自动淘汰磁盘恢复副本，避免丢失首次迁移中的未识别编辑；目录可能随长期冲突增长。

清除浏览器本机数据不删除仓库文件及磁盘恢复副本，刷新会重新加载仓库设计。浏览器撤销栈和历史恢复点不随克隆迁移。

## 写入与兼容边界

服务只监听 `127.0.0.1`。接口限制本机同源、固定目录，不接受任意路径。写入共用项目校验和基准版本比较，通过同目录临时文件、fsync、rename 替换；磁盘互斥锁防止同仓库多个服务同时保存。进程被强行终止可能留下 `projects/.workspace.lock`，确认没有服务写入后才可移除该锁。临时文件和锁不入 Git。Git 不参与此锁，编辑期间不要同时切分支或更新文件。

普通静态服务没有接口时明确提示文件保存不可用，浏览器仍按原链路缓存。`file://` 保留浏览器缓存及手动导入导出，不访问仓库接口，也不自动加载仓库设计；自动迁移请使用启动脚本。工作区接口上限 64 MB，单项目导出上限仍为 30 MB；附件保留原项目限制。
