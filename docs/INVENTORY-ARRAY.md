# 保留原物品的关联阵列（2026-11-07）

## 能力与数据

猫砂 `cat_litter_yanxuan_25kg`、猫粮 `cat_food_myfoodie_2kg`、VIHALS 折叠椅 `chair_ikea_vihals` 、湿巾 `wet_wipes_pack_170` 、佳帮手工具箱 `toolbox_jiabangshou_390` 与方块 `block` 支持关联阵列。纸品继续使用 [paperArray](PAPER-ARRAY.md) 的生产模型内部阵列。没有扩大到普通餐椅、换鞋凳或其它类型。

关联阵列复用原家具记录：每件保留独立ID、型号、原生产构造器、姿态、材质、价格及采购资料；不是将整组缩放为一个实体。数量变化才新增或删除末尾成员，新增件复制首件单品并使用新ID、计划采购状态，已有件的采购信息保留。测距、碰撞、预算与生产GLB继续消费普通家具记录，不重复统计。

`product-rules` 统一声明 `inventoryArray` 能力及字段校验，缺失不补写。每件保存相同的配方及各自序号：

| 字段 | 说明 |
|---|---|
| id | 当前方案内的阵列身份，1–200字符 |
| index | 成员序号，0–199；全组唯一、连续 |
| columns / rows | 每排数量／每层排数，各1–50整数 |
| gapX / gapZ / gapY | 左右／前后／层间距；除VIHALS外均0–1000mm，VIHALS为−1000–1000mm并要求各向中心节距大于0 |
| pattern | grid 或隔排错位半格的 stagger |
| angle | 单件相对阵列平面轴的0／90／180／270度转向 |

数量从实际成员记录派生，不存第二份计数；每组1–200件，全方案仍最多2000件。单件外包复用 `FurnishProducts.dimensions`：折叠椅按实际收起包络（本款深约89.081322mm），不使用470mm展开名义深度。分层高度也用真实当前高度。以首件当前位置／底部为定位基准，填充顺序为左右→前后→向上，末层可不满。修改阵列配方会按该规则重排本组；不能把隔排错位当作实物堆放稳定性认证。

## 转换与编辑

`design-core.attachInventoryArray` 只添加关联配方：逐件核对其实际坐标、离地和朝向与配方相符，差异超过0.001mm／度即拒绝，绝不为满足配方而移动旧物品。转换本身不修改原家具字段或生产几何，也不更换已有 `groupId`。不同位置或不同摞按原排布分别建立阵列。

`applyInventoryArray` 是共用、不可变的工作区操作；预演完成后才由原 `mutate` 应用。属性面板对单件／多选阵列提供数量、行列、间距、排列、转向和解除控件；解除只删除配方，保持物品和位置。物品／图层锁定均阻止编辑，新生成件继承源成员图层，移除成员清理其图层映射。改变数量后撤销／重做会过滤已删除选择并重新展开当前阵列，避免旧选择ID清空整个属性面板。

MCP 沿现有 `get_furniture_parameters` / `configure_furniture`，没有增加绕过保存或撤销的工具。只读 `inventoryArray` 描述当前关联；`arrayEdit` 是不持久化的受限动作：

- 新建：`{memberIds:[原有ID，按阵列顺序],arrayId:新身份,columns,rows,gapX,gapZ,gapY,pattern,angle}`；省略配方值使用1×1、零间距、整齐、0度。须包含当前物品，数量由成员决定。
- 已有关联：`{count,columns,rows,gapX,gapZ,gapY,pattern,angle}` 的合法子集；成员数量和所有生成记录完整预演后一次应用。
- 解除：`{detach:true}`，不附带其它参数。

编辑单件结构或手工移动后再改阵列，会按当前首件重新生成排列；成员规格／姿态不一致则拒绝，避免静默覆盖。阵列不是实时约束求解器，也不推定柜内空腔、承重或取放要求。

## 整体旋转后编辑（2026-11-08）

列／排／层属于阵列自身坐标轴，整体沿X／Y倾斜或绕Z旋转后一起转动。再次修改数量、行列、间距、错位和单件转向时，以首件当前生产几何中心为基准，先生成原局部间隔，再应用同一pose3D刚性旋转；不能把原层间距重新放到世界竖轴。单件平面转向仍相对阵列自身平面，按新姿态包络补偿底部及中心偏移，不改变刚性部件比例。

如果新增件或转向后的包络将低于零离地，全组一起抬高到最低件接地，保持间距；不会只夹住各件高度而挤乱排列。没有新增持久字段或格式版本，旧记录不在加载时改写；下一次有效编辑按首件当前姿态重排。沿用首件的方案离地基准，不新增跨房间不同地面高差的阵列求解。见[旋转回归验收](validation/inventory-array-rotation-20261108/README.md)。

## 二维方向提示（2026-11-08）

同一关联阵列只在所选可见成员的整体外沿显示一套前／后／左／右，不逐件重复。参考当前可见成员中序号最小的产品朝向，用实际投影占地在该朝向上的外包计算位置；图纸旋转、镜像及倾斜投影沿用原绘图方向语义。不同阵列分别显示，普通单件和解除关联后的物品恢复逐件提示。方向显示开关保持。

仅绘图注释合并，不更换家具实体，不改变选择展开、方向测距或净距编辑，不增加保存字段。[界面验收](validation/array-directions-20261108/README.md)。

## 保存、复制及空间语义

显式字段采用v63，当前、命名方案、工作区及恢复缓存接受旧版本。导入核对每组类型、配方和连续序号；缺失字段不改变旧实例。复制给家具和阵列生成新身份，完整剪切移动保留身份，避免副本与原组联动；跨类型替换沿产品字段能力清理，删除／替换后在原规范化链修复剩余序号。命名方案各自独立保存。

生产模型、二维符号、净距／碰撞及三维缓存只读取实际家具尺寸、位置与姿态，不读取关联元数据；因此只建立关联无需使原空间确认失效。调整阵列会改变真实家具记录，沿原缓存和确认链自然失效。纸品的 `paperArray` 仍是直接生成几何的字段，继续纳入原模型／姿态缓存和空间确认，二者不能混用。

## 数量面板（2026-11-07）

统一显示“总数、层、排、列”：层为上下，排为前后，列为左右。总数独立，层数自动派生；改排／列保持总数，直接改层数按满层更新总数，同层数不补满原末层。层仅为界面换算，不新增持久字段，旧排布保持。见[界面验收](validation/array-quantity-ui-20261107/README.md)。

## VIHALS负间距（2026-11-07）

允许外包框交叠以表达折叠椅嵌套靠拢。实际节距=当前朝向下的单件尺寸+间距，须严格大于0；数值范围是软件约束，不是厂家嵌套尺寸。单件平面转向时同步换轴，缩放尺寸或切换折叠状态不能留下非正节距。实际生产椅架仍沿原碰撞／净距检查，不因同属阵列而豁免。只有负间距数据采用v64；其它关联阵列保持v63。具体测试见[验收](validation/chair-negative-gap-20261107/README.md)。

## 湿巾与单件入口（2026-11-07）

湿巾复用现有170×110×70mm的Blender单件资产及独立mountHeight，不改变外观或安装基准。总数、层、排、列、三向间距、整齐／错位与单件平面转向沿现有inventoryArray操作。显式湿巾阵列采用v65；未转换的旧湿巾仍用原版本，既有v63／v64阵列不整体升级。

支持关联阵列的单件即使尚未保存inventoryArray，也显示1件、1层、1排、1列的默认控件；默认配方在product-rules集中定义。读取面板不补写元数据，不移动原物品。首次有效编辑将建立关联和调整数量合为一次mutate，撤销一次即回到原单件。解除后仍可通过数量控件重新启用。多个未关联物品不自动猜测排布或合并。
