# 墙面贴砖厚度与完成面

厚度功能支持整面室内墙侧的瓷砖及粘结层厚度，用于家具布局和柜体净空间核对。毛坯实测墙线、结构厚度、原始结构基线、家具位置和柜体配置独立保留。整面墙的图案参数与立面预览独立保存，见 [墙砖铺贴](WALL-TILING.md)；局部墙裙和施工做法认证仍未提供。

## 使用

选择平面墙体，在属性的「墙面贴砖与完成面」中选择朝向房间的一侧，勾选整面墙贴砖，分别输入瓷砖／粘结层厚度并应用。承重墙或外墙的结构锁定不妨碍设置饰面。同一堵墙可按两侧分别设置；同侧面向不同物理房间的范围分别列出。方位采用原图坐标，不随图纸显示旋转变化。

自定义户型也可以选择窗、门或建筑推拉门，在属性中修改其宿主墙面的贴砖厚度。此入口与选墙共用同一设置，适用于导入图中没有可单独点击的普通墙段的洞口宿主；原始结构锁定仍只限制门窗几何，不限制饰面设置。改动、撤销、刷新和项目保存均沿用原方案通道，不修改洞口、毛坯基准或家具。

两层厚度均为绝对 mm，各接受 0–200 mm（建模输入范围，不是厂家要求）。总增厚等于两者之和。没有施工资料时不填默认值；勾选但任一层留空时保留未知，空间核对显示 pending，不按零厚度宣称净尺寸已确认。未设置饰面的旧墙沿用毛坯表面。

二维以浅褐色带表示实际增加的占用，保留原毛坯墙体；三维分别生成粘结层、瓷砖实体。门窗正面按现有洞口高度留空，不生成侧壁包砖。房间截面净尺寸、完成面净面积和家具净距即时派生。原始图纸外围尺寸链、墙体结构编辑与墙间净距编辑继续表示毛坯结构；已保存测量线仍是固定端点，饰面修改后需重新测量。地面预算继续按原毛坯面积计算。

修改厚度只改饰面设置，不调用家具推离或厨房自动避障。已贴毛坯墙的家具可能因新饰面产生占用提示，用户主动移动或按净距数字定位后才改变位置。柜体制作尺寸与安装／收口余量分开，不自动缩小柜体。常规拖动仍保留原释放推离行为，但障碍改为完成面。

## 数据契约

可选 `work.wallFinishes`：

```json
{
  "version": 1,
  "surfaces": [
    {
      "wallId": "dxf_wall_id",
      "side": 1,
      "range": [0.05, 0.95],
      "tileThickness": 10,
      "bondThickness": 15
    }
  ]
}
```

示例数值仅说明格式。缺少 thickness 键代表未知，不能用 null 或字符串代替。最多 500 项；同一墙侧不能有正长度重叠范围。清除最后一项时删除整个可选字段。家具替换、采购及风格编辑不修改墙饰面。

`wallId` 对自定义户型使用草稿稳定墙 ID；内置示例使用原模板墙段的 `builtin_N` 标识，在拆除过滤后仍保留原序号。`side` 是标准坐标轴上的负侧／正侧，不依赖墙端点顺序。`range` 是沿标准坐标轴从小到大、相对于原完整墙矩形长度的归一化范围，用于区分同侧不同物理房间；不是局部贴砖高度。范围来自真实物理房间边界，功能区分合不创建新墙侧。

真实导入图可将门窗宿主单独拆成没有普通墙段的来源墙，仍识别其窗台下／洞口上方的室内完成面。凸出墙端也按实际房间边界识别：可选 `cross:true` 表示原墙轴线的端面，范围改以墙矩形的横向跨度归一化；缺失时保持原纵向墙侧语义。绑定、重复校验、编辑、复制转换和恢复均区分纵侧与端面。仅识别房间已有边界，不把功能区分界或门窗洞口侧壁当作新墙。

墙体重建后仍通过稳定墙 ID 及侧别关联，范围取当前暴露部分的交集。原墙缺失、侧别不再暴露或范围发生变化时保留记录并提示重新核对，可在房间完成面属性中移除。不会按最近距离猜另一堵宿主墙。内置户型创建编辑副本时显式转换墙 ID、范围与平移；复杂重分段可能保留待核对提示。

## 几何与调用链

- `src/core/wall-finish-core.js` 是浏览器／Node 共用规则，负责校验、墙侧识别、修改提案、完成面派生、墙高、复制映射及仅饰面修改判定。建筑饰面参数由此模块集中管理，不新增家具类型字段或复制产品白名单。
- `project-core.effectivePlan()` 保留毛坯 `walls/rooms`，附加非持久 `wallFinish`。`FurnishWallFinish.spatial()` 返回布局边界副本，追加饰面实体并使用裁切后的房间，重复调用不再叠加。
- 原始物理房间与饰面带按精确平面分解取差集，交角按并集扣除一次，保留功能区、凹口及孔洞。已知饰面在门窗下方／上方生成带实际底顶标高的实体。
- `snapRects()`、普通距墙／四向定位、测量、厨房拉伸、摆放建议与项目实体／开启／操作区／通道检查共用完成面。原柜门核心继续提供生产板件的三维扫掠；饰面传入相同开启相交接口。墙窗平面吸附和数字移动路径仍沿用原保守语义。
- `src/render/wall-finish-model.js` 是实际三维生产构造器，边界统一 mm→m。剖切只截取显示高度，不修改保存参数。漫游碰撞包括落地饰面。
- 二维、三维建筑／标签缓存和空间确认输入覆盖饰面配置及派生几何。价格、采购、颜色不进入空间输入。仅缓存最后一份派生结果，并返回独立数据副本。
- 2D SVG／PNG／打印保留饰面，DXF 将毛坯墙保留在 `WALLS`，饰面另放 `WALL_FINISHES`，房间轮廓采用完成面。

## 保存、恢复及版本

所有编辑通过现有 `mutate()`、JSON 快照、撤销重做、自动保存、命名方案和恢复点完成。`commit()` 对仅饰面变化跳过家具及厨房联动；含饰面的恢复保留已有厨房避障配置，不用新完成面重算。常规家具编辑的原厨房自动避障仍按毛坯结构工作；饰面冲突由布局核对提示。

旧项目缺字段时不补饰面、不推定厚度、不移动家具。持久化只保存输入，完成面从毛坯重建，多次恢复不累计增厚。XY 标定变化不缩放两层毫米厚度。复制项目保留稳定墙 ID，复制家具不携带墙饰面。

带饰面的当前或命名方案导出 `furnish-project` 版本 2；仓库中任一工作槽或命名方案含饰面时，`furnish-workspace` 外层版本为 2。新版读取 1／2，未使用饰面的文件仍写版本 1。旧版通过不支持的外层版本拒绝打开新语义文件。原浏览器缓存 v2 存储机制保持，本变更不承诺将含饰面的缓存交给旧代码降级运行；带饰面的内置户型使用项目文件分享，避免旧分享链接忽略厚度。

## 验证与边界

专项 Node 回归：`tests/test-wall-finishes.cjs`，覆盖毛坯不变、精确净尺寸、吸附／数字定位、接触及容差两侧、旋转镜像／编组、不同墙侧、门窗标高、未知值、非法输入、版本、复制、标定、重复恢复、实际 commit 和真实 Three.js 层几何。

专项浏览器：`node scripts/verify-browser.cjs wall-finishes`。使用合成项目与隔离存储，在 HTTP／断网 file:// 下验证真实表单、非法输入原子性、未知提示、撤销重做、家具定位、刷新、下载再导入、命名方案、自动避障配置保持、3D 和 390 px 窄屏。结果摘要记录在对应改进记录中。

边界：当前户型核心仍只支持水平／竖直结构墙；家具可以旋转、镜像。墙裙、局部高度、洞口侧壁、收边压条、防水／找平层及施工切砖优化未建模；整面墙图案排版见独立墙砖功能。厚度过大可使房间净空间消失，会保留设计并产生边界冲突。空间检查保留既有墙体 SAT 容差（5 mm），数字定位沿用其更严格路径校验；未知家具高度保守参与。未进行施工级校核或实机触屏验收。
