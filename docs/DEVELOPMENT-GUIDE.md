# 成长型项目的扩展与复用

本约定来自 2026-10-12 的门窗、柜体、设备模型与项目一致性维护。模块导航见 [ARCHITECTURE.md](ARCHITECTURE.md)，当日事实与缺陷处置见 [当日审视](REVIEW-2026-10-12.md)。

## 新功能的最小完整链路

新增产品首先确认 type、默认规格和资料来源，再检查下列位置；无需机械修改所有文件，必须说明不适用项。

| 责任 | 入口 | 需要确认 |
|---|---|---|
| 库定义 | `src/data/catalog.js` | 类型、尺寸、高度、价格依据、不覆盖已有型号 |
| 产品能力 | `src/core/product-rules.js` | 默认高度、安装语义、字段范围、新建/迁移/替换；先定义规则再由各层消费 |
| 数据规则 | `src/core/design-core.js` | 高度/安装基准、缩放、旧数据、复制/替换语义 |
| 专用参数 | `src/core/cabinet-core.js` 等 | 约束、不可变编辑、旧默认值、结构版本 |
| 导入/导出 | `src/core/project-core.js` | 当前/命名方案校验及往返 |
| 属性 | `src/ui/property-panel.js` 与专用编辑器 | 合法 0 值、锁定、`mutate()`、撤销/保存 |
| 展示 | `src/render`、入口 3D 构造器 | 2D/3D 一致、生产模型复用、缓存签名 |
| 空间核对 | `layout-geometry.js`、`project-core.js` | 高度错位、未知高度、安装规则边界、确认失效 |
| 验收 | `tests/test-*.cjs`、模型文档 | 实际几何、状态往返及必要的界面验收 |

## 已证明有用的经验

1. **基准语义先于字段命名。** 花洒的混水器中心离地与软管最低点不是同一高度。迁移应换算并保持原物理位置；再次恢复不能继续漂移。默认值变更只作用于新建或缺失字段。
2. **世界点和附着点分开。** 固定插座保存世界坐标，不随热水器拖动；喷枪等产品附件跟随产品的局部旋转/镜像。不能共用一种定位假设。
3. **嵌入关系依据空腔，不依据名称。** 冰箱豁免应验证净宽、净深、净高和姿态；进入侧板、顶板或与第二台冰箱重叠仍告警。嵌入成功不代表满足散热要求。
4. **派生尺寸与独立参数分开。** 餐边柜总深取各部分的最大值，冰箱框深、下柜深、上柜深独立保存；宽度缩放保留冰箱净宽。先计算完整结果再应用，失败不产生部分修改。
5. **复用生产构造器。** 预览、应用和几何测试共用模型。用真实 Three.js 外包框、射线、转轴与开合位移验证，而不只检查源代码里出现了某个常量。
6. **碰撞需要垂直范围。** 共用 `FurnishGeometry.verticalOverlap()`；已知高度不相交时免除实体重叠，未知高度保持保守。画布保留桌椅推进例外，全案仍提示人工核对。
7. **确认本身是缓存。** 空间确认现为 v3，记录平面几何、垂直/镜像/柜体配置、实际物理房间、净高、梁投影和通道阈值。价格与采购编辑不失效；旧不完整确认重新核对。
8. **回归必须可交付。** 本机发现并执行的测试也必须可被 Git 跟踪。`check.cjs` 动态报告套件/户型数量，空测试目录失败；提交审查时检查新增测试确实进入变更。

## 后续扩展按需求推进

当前原生脚本、共享全局状态和入口内联 3D 仍可使用。优先通过有证据的行为问题逐步建立接口，而不是一次性改为框架或打包系统。

- 默认高度、安装参数、迁移与替换能力已收敛到 `product-rules.js`，目录、校验、属性和相关渲染已消费。新增类型按 [PRODUCT-RULES.md](PRODUCT-RULES.md) 接入，保留历史回退；柜体结构和专用几何继续交给各自模型。
- 柜门/抽屉已增加高度分层，上翻门使用竖向扫掠剖面，并检查家具、墙和吊顶；未知梁高保留待核对。维护规则时交叉验证生产模型，再验证实际恢复链路。详见 [三维开启检查](CABINET-OPENING-3D.md)；其他柜体空腔及多门同时运动仍未逐板模拟。
- 项目格式当前为版本 1；新增不兼容语义应提供显式迁移入口和历史夹具，拒绝无法识别的版本，不静默覆盖用户数据。
- 三维拆分需要先建立 `file://`、本地服务、切换方案、旧实例和触屏的验收基线，保持离线依赖策略。
- 密集模型增长时，用真实用户样本测空间核对耗时和 3D 内存；只优化实际瓶颈，避免依赖单个 2000 件合成场景做普遍承诺。
