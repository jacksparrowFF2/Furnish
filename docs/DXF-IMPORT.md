# 真实 DXF 图纸的导入与诊断

Furnish 支持二维正交墙中心线，以及闭合墙体轮廓转换。能解析一个 DXF 文件，不等于所有 CAD 实体都能还原成户型。闭合轮廓也可能是墙体自身，不能仅以“找到闭合房间”作为导入正确的依据。

## 墙轮廓导入

1. 导入文件，选择 **墙轮廓 → 中心线与窗洞**。同时含墙轮廓和窗位层的图纸会建议这个模式。
2. 勾选完整墙体图层并指定类型；例如普通轮廓层和单独的承重层。图层名只提供建议，“房屋”仍须指定类型，不能据此确认承重或外墙。
3. 勾选窗位层与水气点位层。矩形窗位在两端有邻接墙时，生成带实际厚度的基墙及窗洞；下水、燃气圆形点位保留坐标、半径和源图层。
4. 设置初始窗台高与窗顶高。默认 900 / 2400 mm 是录入初始值，二维轮廓未提供这些高度，导入后仍标为待核对。
5. 可将同线墙端间 600–1400 mm 的断口生成待核对门洞。超过范围的通道保持原样；没有明确相邻墙端、被实体占用或候选重叠时不自动推导。只有一个连通室外的候选时预填为入户门，开启方向仍需核对。
6. 查看转换预览及空间面积，导入后核对门窗和墙类型，保存原始结构。水气点位显示于描图编辑器、主画布和平面成果，并随项目和命名方案保存。

转换按轮廓内部区域生成矩形墙段，局部墙厚来自几何；端面以显式端帽保存，避免通用墙交点延伸改变图纸。折形墙允许墙段在拐角相交，但它们的并集必须覆盖原轮廓。重复轮廓边不成为额外墙；不同类型的实心轮廓重叠时拒绝转换，保留承重分类。

闭合标志缺失但首尾已连接的多段线也可识别；重复尾线仅在被已有轮廓边覆盖时移除。明显斜墙、弧段、三维墙、块与填充、未解释的散线，以及无法用 60–600 mm 墙厚表示的细碎区域会拒绝导入。允许轻微倾斜最多 2 mm、0.5°，报告最大端点移动量；转换结果仍受 100 墙段上限约束。

## 已提供的诊断

- 保留 ENTITIES 中所有图层的实体类型统计，包括只有圆、块或填充的图层；这些图层会在界面中标明未转换。
- 按名称提示墙体、承重、隔墙、外墙、门窗及辅助参考用途。建议需人工核对；“房屋”不默认分类为非承重墙，也不根据墙厚判断承重。
- 原图预览与修复预览分开。即使单位、类型或转换校验失败，原图可解析线条仍可查看，未选图层淡显。
- 对闭合细长轮廓给出疑似墙体轮廓提示，对跨层重合边、所选层中未转换的几何实体给出诊断。轮廓检测是启发式提示，可能漏检或误报。
- 有风险提示时，需要核对当前线条和忽略实体后才能继续尝试。改变单位、图层、类型或修复设置后重新核对；双线转换和房间校验仍可能拒绝导入。
- 中心线模式仍把门窗层作为参考；轮廓模式可选择矩形窗位生成窗洞。独立飘窗参考线暂不自动生成三面窗。

用命令行对任意本地图纸做只读诊断，并可生成离线 HTML 报告：

```powershell
node scripts/inspect-dxf.cjs 'D:\图纸\户型.dxf'
node scripts/inspect-dxf.cjs 'D:\图纸\户型.dxf' --html 'D:\图纸\导入诊断.html'
```

报告包含图层统计、矩形候选尺寸、原图线条预览与现有中心线/双线转换试验。试验统一假设 200 mm 墙厚，未分类的墙体候选暂设为非承重，只用于暴露转换错误，不生成项目，也不能作为实际结构分类或面积依据。源 DXF 不会修改。

## 真实图纸验证

运行只读区域对照、窗洞检查和项目往返验证，可另外保存可加载项目与离线对照报告：

```powershell
node scripts/validate-dxf-outline.cjs 'D:\图纸\户型.dxf' 'D:\图纸\Furnish导入验证'
```

这个命令根据图层名采用承重／外墙／隔墙建议，其他墙体候选暂按可修改墙处理，并在报告中明确记录映射。正式导入仍需在界面核对类型。输出 `imported.furnish.json`、`validation.json` 和 `validation.html`，原 DXF 不修改。

本次实际样本（149685 字节、毫米制）转换得到 47 段墙中心线、2 个独立房梁投影、7 个窗洞、3 个待核对门洞、3 个闭合空间、2 个下水点位及 1 个燃气点位。3 段承重矩形保持 233 / 236 / 230 mm 厚度，空间净面积合计 70.252023 m²。原图有一条轻微倾斜长边，最大扶正调整为 0.5 mm。

对源轮廓与转换后的填充区域检查 1248 个坐标网格区域，超出已报告扶正容差的差异为 0；窗洞与原图矩形位置一致且未被墙体遮挡；全部水气点位坐标和半径一致。浏览器已验证真实 DXF 导入、保存、刷新、导出项目内容及在新环境重载，原中心线综合模板仍能导入。

`node scripts/check.cjs` 运行全部回归；新增 `tests/test-dxf-outlines.cjs` 覆盖折墙填充区域、局部墙厚、窗洞、门洞候选、点位、单位转换、待核对状态和项目往返。私有真实 DXF 不随代码复制，实际样本验证需显式传入本地路径。

## 后续扩展

1. **扩展图层映射。** 在现有墙层类型、窗位和水气层选择基础上，支持用户指定名称不标准的图层、房间轮廓及其他参考实体用途，并提供参考对象显隐与属性编辑。
2. **复杂轮廓与类型冲突。** 在现有正交轮廓局部拆分基础上，提供跨类型重叠位置的交互处理和更大图纸的分区转换；支持更多形状时仍需追踪来源，不能静默丢弃承重属性。
3. **一般门窗符号与飘窗。** 在矩形窗位和直线门洞候选基础上识别门扇符号、块与三面飘窗。缺失窗高、开启方向或进深时保持待核对状态。
4. **复杂拓扑和异常定位。** 进一步支持柱岛、庭院以及断口、交点和未处理实体的逐项定位；完善原图叠加和端点编辑。
5. **真实图纸回归集。** 在得到授权的脱敏样本上验证墙段类型、厚度、窗数、位置、房间净面积与项目往返；覆盖变厚墙、重复边、断口和单位/编码差异，再扩展 INSERT、HATCH、弧线和文字。

目前支持正交闭合墙轮廓、矩形窗位、有限直线门洞候选和圆形水气点位。一般门扇符号、块、填充、弧墙和自动房间用途识别尚未实现。超出这一范围时，可在 CAD 中另存连续墙中心线，按结构资料分类，在 Furnish 中补录门窗。

## 房梁与房间名称

轮廓模式将“房梁／横梁／beam”图层识别为独立顶部投影，也可在图层类型中选择“房梁”。房梁以紫色虚线显示，保留源图层、实体编号与轮廓；不加入墙体、房间分割、地面扣减或地面家具碰撞计算，也不会生成门洞。二维 DXF 未提供梁底与梁顶高度时保留待核对状态，目前仅显示二维参考，尚不生成三维梁。混在“房屋”图层内的梁应在 CAD 中移到单独图层后再导入，程序不靠宽度猜测梁或墙。

在主画布点击已识别房间，在右侧“名称”栏输入名称，离开输入框后保存；“装修设计工作台 → 设置房间用途”可以批量修改名称与用途。名称、用途及材料独立保存，项目导出与重新载入也保留名称。开放空间内可在“编辑户型 → 划分功能区”中点击两点设置水平或垂直分界，分界自动延伸到当前区域边缘，为两侧分别命名并指定用途；可继续细分、撤销／重做或删除分界（其后续细分会一并移除）。也可在已选房间的属性中点击“划分功能区（不加墙）”。功能区各自统计面积，可分别设置地面材料，且互不重叠、不漏算；顶部房梁不会作为功能区分界。

功能区随 .furnish.json 项目保存，包括自定义名称、用途、分界及命名方案；刷新、导出和重新加载都保留。重新上传 DXF 替换几何会重新录入，功能区不会写回原始 DXF。原有直线分界仍须把当前空间分成两个连续区域，最多 50 条；新增矩形和多边形指定区域最多 50 个，每个多边形最多 100 个顶点。物理空间轮廓独立保留，用于墙面工程量和通道检查；功能分界不产生墙体，家具可跨区，净面积与地面预算不会重复计算。

## 矩形、多边形与边界调整

- “矩形功能区”：在空间内部按住鼠标拖出矩形，松开后命名并指定用途。
- “多边形功能区”：依次点击顶点，点击起点或“完成多边形”闭合；支持斜边和凹多边形。Esc 取消未完成绘制。
- “调整功能区边界”：点击区域或侧栏“调整边界”，拖动橙色顶点或边中点；矩形调整保持直角。原有水平／垂直分界也可拖动。无效最终位置会回退整次拖动；取消、撤销／重做同样保持事务完整。

指定区域必须完整位于所选原空间内，不得越过墙体、重叠其他指定区域或自交；允许共边、共顶点，面积至少 0.01 m²。区域的剩余部分自动扣除已指定面积，支持凹形、空洞和多个不相连的部分，不漏算或重复计入全屋面积。剩余区域也可命名和设置用途。

调整始终保留区域编号，名称、用途、地面材料和命名方案由该编号关联，编辑后及 .furnish.json 重载后都保持对应。即使剩余区域暂时没有面积，其设置仍会保存。原有直线分界在指定区域旁使用时会重新关联其所属空间，禁止横穿指定区域；删除直线分界会保留矩形／多边形区域并恢复其所属空间。

二维按外轮廓和空洞绘制，三维按无重叠凸区域铺地，避免空洞被地面补满。地面预算按各区真实面积和材料计算，墙面工程量、家具碰撞和通道检查保持按物理墙体／空间计算。

回归测试 `test-free-zones.cjs` 覆盖斜边、凹形、空洞、相邻共边、剩余区域、边界调整、重叠／越界／自交拒绝、名称用途保留和项目往返；`test-free-zones-3d.cjs` 用页面实际内嵌的 Three.js 验证三角面不覆盖其他区域或空洞。

## 共用边界、吸附和精确尺寸

在“调整功能区边界”中选择区域，拖动共用边的橙色中点，相邻区域会同步改变。支持一条长边对应多个邻区的 T 形交接、部分共用边和斜边；必要时在邻区轮廓插入交接顶点。共用边移动前后覆盖范围保持一致，拒绝缝隙、重叠、自交或越界。外侧边可改变区域范围，剩余面积自动调整。一次拖动及其所有联动修改属于同一条撤销记录；无效最终位置会整次恢复。

拖动时在 8 个屏幕像素内吸附实际墙内表面和顶点，随缩放保持同样的操作距离；顶点拖动优先吸附顶点，边拖动保持原方向并对齐顶点或平行墙面。蓝色圆圈标出吸附位置。按住 Shift 暂停吸附。顶部房梁不参与吸附目标。

选择区域后点击“精确边界尺寸”，按画布上的顶点编号选择边或顶点。边显示当前长度，可输入带正负号的法线偏移，界面注明正向移动方向；顶点可输入 X/Y 毫米坐标。矩形顶点调整仍保持直角。原直线分界也提供“精确分界位置”。坐标原点为描图画布左上角，X 向右、Y 向下；均按图纸比例换算为真实毫米，精确输入不再自动吸附。

几何运算按毫米处理精度，轮廓简化另检查面积守恒，避免非整数图纸比例产生的微小碎片造成少算。区域 ID、名称、用途和材料不因联动更换，保存及重新载入 .furnish.json 后保持对应；原 DXF 不写入功能区。

`tests/test-zone-boundaries.cjs` 覆盖共边、T 形交接、部分共边、反向斜边、越界拒绝、面积守恒、微小碎片及项目往返。`output/playwright/shared-boundaries-check.cjs` 从本地真实 DXF 重新转换，验证共边拖动、123.4 mm 偏移、顶点绝对坐标、墙面／顶点吸附、撤销／重做、刷新和导出后新环境载入。示例区域只用于验证操作，不代表实际装修布局。验证中客餐两区总面积 15.25 m²，全屋净面积 70.252023 m²；47 段墙、7 个窗、3 个门、2 个房梁投影及 3 个水气点位保持一致。

## 多边形顶点增删与实时反馈

在“调整功能区边界”中选择区域，点击“增加顶点”，再点击橙色边或中点，在投影位置插入顶点；新增点位必须在边内部，不能重复已有点位。共用边上的新增点同步插入相邻区域。之后可拖动新增点形成折线，共用轮廓仍联动。

点击“删除顶点”，再点击橙色顶点，连接它的前后两点；共用折点先联动拉直，再删除两侧冗余点。必要的邻区交接点会保留。多边形至少保留三个顶点、最多一百个；自交、越界、面积过小、重叠或破坏共用覆盖范围的操作不会应用。每次增删及全部邻区变化是一次撤销记录，Esc 退出增删模式。

选中区域的每条边显示毫米边长；侧栏显示全部有效区域面积及全屋总面积，画布浮动提示显示选中区和当前联动邻区的面积。拖动过程中提示“墙面吸附”“顶点吸附／对齐”“未吸附”或“吸附暂停（Shift）”；无效位置显示最后有效边界，松手后恢复整次拖动。以上反馈基于当前有效几何，不会把尚未接受的位置计入面积。

`output/playwright/zone-vertices-check.cjs` 用真实图纸的相邻区域验证共边插点、实时边长和两区面积变化、总面积守恒、拖动折点、共用顶点删除、整组撤销／重做、吸附文字、刷新及项目重新导入。验证后的项目 `zone-vertices-verified.furnish.json` 保留新增折点；名称、独立用途和面积与保存前一致。三维地面仍通过现有凸分解绘制，功能区增删顶点不会新增墙体。

## 折线拆分与相邻区域合并

在“编辑户型 → 折线拆分区域”中先选择一个连续区域，再在外边界点击起点、依次点击折点，最后点击另一处外边界。起止点在 10 个屏幕像素内吸附所选外边界，点击终点后打开两个区域的名称／用途设置；也可点击“完成折线拆分”。侧栏每个区域也有“折线拆分”入口。原房间、已指定区域和剩余区域都可拆分；折线须在区域内部，不能自交、重复点位、经过孔洞或跨墙，且必须形成两个连续区域，每区至少 0.01 m²。Esc 或“取消折线”放弃尚未确认的路径；正在绘制时须完成或取消路径才能保存户型。

“合并相邻区域”提供具有共用边的邻区列表。选择邻区后，可选择从当前区或邻区保留名称与用途，也可修改结果名称和用途。只共顶点、存在缝隙或分属不同物理空间的区域不能合并，不会删除实际墙体。一次合并两个区域，可继续合并；原直线分界支持同一级两侧合并，有后续分界时须先逐级合并。

拆分与合并结果使用独立区域编号，明确保存各自的名称、用途和几何；其他区域保持原编号与设置。每次操作是一次完整撤销／重做记录。已有孔洞通过多轮廓保留，不会作为新增地面面积；多轮廓也随项目保存。拆分要求所选区域是一个连续外轮廓，原本包含多个不相连部分的区域暂不支持一次折线拆分。新区域轮廓仍受最多 100 个总顶点、20 个轮廓和 50 个指定区域的复杂度限制。

程序校验前后覆盖范围、各区面积之和与全屋面积；斜边相交产生的微小反向碎片仅在局部面积误差小于 0.001 mm² 时简化，并再次校验覆盖。`tests/test-region-operations.cjs` 覆盖折线、孔洞、旧直线分界、相邻／只共点／不相邻合并、无效路径、名称用途、面积、项目往返及微小斜边碎片；Three.js 回归同时验证新区域的孔洞和地面覆盖。

真实图纸浏览器验证 `output/playwright/region-operations-check.cjs` 将原 6.783501 m² 区域拆为“起居区 / 客厅用途”3.494251 m² 与“阅读区 / 书房用途”3.289249 m²，再选择保留起居区设置合并。全屋面积按六位小数保持 70.252023 m²；前后覆盖差异约 0.000375 mm²，在浮点容差内。拆分与合并都通过保存、刷新、导出及新环境重新加载，47 段墙、7 个窗、3 个门、2 个房梁投影与水气点位保留。操作示例不代表实际装修布局。
