# Blender 建模整链路验收

2026-10-30。固定产品的默认建模路线不变；本入口串联已有专项验收，减少临时脚本与人工搬运。**目前完整配置只支持 `washer-tg10k60w`**，没有将圆门规则推广给其它产品，也没有新增网页任意模型导入功能。

## 运行

```powershell
# 沿用项目 Playwright 配置；首次使用先安装项目浏览器依赖。
$env:FURNISH_BROWSER_CHANNEL = 'msedge'
node scripts/verify/verify-model-pipeline.cjs washer-tg10k60w gpu
# 可改 auto 或 cpu；auto 的实际设备和回退原因会记录在报告里。
```

`FURNISH_BLENDER` 显式设置优先，其次为 Scoop 的 `apps/blender/current/blender.exe`，商店版作为备选。复用 `blender-server.cjs`，不固定版本目录，不自动重试不同版本；失败时保留现场和日志。

运行目录为 `output/model-pipeline/washer-tg10k60w-<随机后缀>/`，包含独立副本、逐阶段日志、`report.json`、源资产哈希及全部导出产物。打印当前阶段；任一阶段失败即停止，报告记录失败阶段，不覆盖上一份验证结果。

流程依次执行：

1. 复制代码、离线依赖和方案到私有工作区，固定本次实际 Blender 路径。
2. 新目录后台建模，导出前预检，保存可编辑 BLEND 和 GLB。
3. 对新源工程做真实 Blender 故障注入检查，再独立回读／严格发布 GLB。
4. 仅在副本内把新产物放入标准路径，验证生产几何、材质、状态往返和空间确认。
5. HTTP 与断网 `file://` 验收同源应用／预览、尺寸、开合、撤销恢复、窄屏和正式生产导出。
6. Blender 回读两种入口的生产 GLB，检查部件、门轴、离地和透明属性。
7. 从正式生产构造器生成三个固定机位场景，经正式本地渲染 API 渲染，下载 PNG／BLEND／GLB。
8. 重开三个下载工程，核对部件、尺寸／材质、相机和渲染设置。

源仓库正式 JS／GLB／BLEND 及真实方案在运行前后校验哈希。`passed` 表示上述自动链路通过，**不包括目视还原度批准**。其它工作在运行期间修改源文件时，报告标记源变化，需人工分辨，工具不回滚他人修改。

## 导出前预检

`scripts/lib/blender_asset_preflight.py` 在作者保存／导出前执行，目前接入通用洗衣机与 TG10K60W 作者脚本。消费对应核心 spec，检查公制与单位比例、有限坐标、非空网格、部件集合及稳定身份、单一声明材质、所有面的有效材质索引，以及运动角色、随动归属、轴心、轴向和静止变换。错误包含对象名。

预检不自动修补未知工程，不替代独立发布器的材质限制、尺寸／几何和轴心复核。后续产品编写相应适配契约；多材质产品不能强制套用洗衣机单材质规则。

`scripts/verify/verify-model-preflight.py` 对新源工程注入空材质、错误面索引、重复身份、脱离运动父节点、错误轴心、错误单位和非注册部件，验证逐项拒绝；不保存故障工程。

## 固定视觉场景

`verify-model-studio.cjs` 提供 `tg10k60w-studio-v1`：标称595×560×850mm、零离地、正面／斜视闭合及110°开门，方形512px、36°透视相机；位置／目标及光照写入 `studio/studio.json`。固定白色主光强度3，正式基础渲染采用 AgX、曝光0和标准世界光。110°是既有模型假设，不是厂家实测限位。

模型与导出器均为正式生产入口，夹具有明确坐标基准。固定灯光仅作用于隔离验收场景，不改真实户型、用户机位或全局设置。三个 PNG 分别位于 `studio/front/`、`studio/oblique/`、`studio/open/`。与参考图和上一有效版本目视对照正面分区、门窗比例／位置、内件、曲面法线、材质和运动。

这些图用于重复对照，不是绑定1601精修工程的效果图；简单 Alpha 不代表物理折射。不同 Blender／设备版本可能有像素差异，不做严格逐像素相等断言。新产品应按其规格和运动机构定义机位及适配检查。

## 扩展边界

新增配置复用隔离、阶段日志、哈希及真实 API 下载机制，显式提供作者／发布命令、专项套件、生产回读和视觉夹具。暂不统一全部产品描述或增加全屋性能基线：前者应依据重复内容逐步收敛，后者须用真实多模型方案测量后再优化。
